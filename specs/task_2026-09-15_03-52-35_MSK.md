# Задача 21204

Источник: https://carcraftpro.bitrix24.ru/company/personal/user/302/tasks/task/view/21204/
Постановка получена из сообщения пользователя в текущей задаче.

## Требования

После прямого нажатия кнопки «Войти» в header и успешного входа либо регистрации пользователь автоматически попадает в свой ЛК. Вход через корзину, избранное и остальные точки входа сохраняет существующее поведение. Изменять внешний вид кнопки не требуется.

## Текущее поведение и основание

- `frontend/components/TheHeader.vue`: кнопка «Войти» и событие избранного открывают одну модалку через `showAuthModal`; `handleAuthentication` закрывает её и переносит гостевое избранное без перехода.
- Там же `accountRoute` уже учитывает `authStore.homeRoute`, контекст витрины и `buildWorkspaceLocation`.
- `frontend/features/auth/store/auth.ts`: `homeRoute` выбирает `/workspace` для бизнес-ролей и `/cabinet` для остальных; вход может запускать отложенный переход из `redirectAfterLogin`.
- `frontend/features/auth/components/AuthModal.vue`: успешные вход, регистрация и подтверждение телефона завершаются событием `authenticated`; MFA может продолжаться на отдельной странице.

## Планируемые изменения

1. Явно различать прямое нажатие «Войти» и остальные причины открытия модалки. Намерение перехода относится только к конкретной попытке входа.
2. После полной успешной авторизации из кнопки header переходить по существующему маршруту ЛК с актуальной ролью и контекстом витрины. Сохранить перенос гостевого избранного и корзины; ранний выход для иных ролей не должен блокировать переход.
3. Сохранять намерение при переходе между входом и регистрацией, подтверждении телефона и MFA. Сбрасывать при отмене и после использования; не оставлять его для следующего входа из корзины или избранного.
4. Исключить конфликт с отложенным `redirectAfterLogin` для прямого входа из header, сохранив существующие перенаправления остальных сценариев.
5. Добавить регрессионные проверки на базе существующих frontend-тестов. Реализацию и независимую проверку выполнять с подагентами согласно AGENTS.md.

## Критерии готовности

- Прямое нажатие «Войти» в header → успешный вход → ЛК соответствующей роли.
- Та же точка входа → регистрация и необходимые подтверждения → ЛК.
- MFA завершает исходное намерение перехода только после успешной авторизации.
- На брендированной витрине сохраняется предусмотренный маршрутизацией контекст.
- Вход из корзины продолжает текущий сценарий оформления; вход из избранного и иных точек не получает нового перехода в ЛК.
- Закрытие модалки после нажатия «Войти», затем вход из другой точки не приводит к ложному переходу в ЛК.
- Ошибка авторизации не вызывает переход. Перенос гостевых данных сохраняется.

## Реализация и проверка

- `TheHeader.vue` хранит намерение только текущего открытия; переход использует существующий `accountRoute` и выполняется после переноса гостевых данных, включая его ошибку.
- `AuthModal.vue` передаёт opt-in намерение в login и MFA; после размонтирования игнорирует поздние ответы авторизации и отменяет таймер события успеха.
