# Bitrix #21802 — сохранить черновик условий при загрузке PDF

- **Статус:** требуется подтверждение спецификации
- **Задача:** https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/21802/
- **Ветка:** `bugfix/21802`

## Текущее поведение

Лизинговая компания заполняет условия предварительного или итогового КП, но ещё не отправляет расчёт клиенту. При выборе PDF-файла выполняется `POST /api/v1/leasing/applications/{id}/response-pdf`, после успешной загрузки страница заново получает состояние ответа.

Полное обновление состояния передаёт в `LeasingProposalForm` новый `initialProposal`. Watcher формы повторно вызывает инициализацию полей. Пока расчёт не сохранён сервером, предложения нет, поэтому введённые пользователем значения заменяются начальными значениями формы.

## Требуемое поведение

После успешной загрузки или удаления PDF:

- файл отображается в форме;
- введённые, но ещё не отправленные условия КП остаются без изменений;
- уже сохранённые условия КП также отображаются корректно;
- состояние формы обновляется из сервера только при первичной загрузке заявки, явном обновлении страницы или после успешной отправки расчёта.

## Бизнес-цель

Лизинговая компания должна иметь возможность прикрепить PDF к расчёту без повторного заполнения условий. Это предотвращает потерю работы и риск отправки некорректного предложения.

## Планируемые изменения

1. В `frontend/pages/workspace/leasing-applications/[id]/index.vue` заменить полное обновление состояния после upload/delete PDF на точечное обновление PDF-метаданных, возвращённых API. Это не меняет `initialProposal` и сохраняет черновик формы.
2. Не менять `LeasingProposalForm.vue`: повторная гидратация формы остаётся корректной при первичной загрузке и после отправки расчёта; для PDF-операции она больше не вызывается.
3. Добавить frontend-регрессию: при несохранённых значениях формы успешная загрузка PDF не должна вызывать повторную гидратацию и сброс значений; при первичной загрузке и после отправки расчёта гидратация сохраняется.
4. Проверить архитектурные тесты, production build и локальный Docker-сценарий с доступными тестовыми данными.

## Критерии приёмки

- Пользователь вводит аванс, срок, выкуп и ежемесячный платёж, выбирает PDF — значения в полях остаются прежними.
- Успешно загруженный PDF виден в обеих формах КП.
- Удаление PDF также не сбрасывает несохранённые значения.
- После отправки расчёта форма отображает значения, сохранённые сервером.
- Ошибка загрузки PDF не меняет значения условий.
- `bun run test:arch` и `bun run build:frontend` проходят.

## Границы и риски

- Backend-контракт и данные предложений не меняются: endpoint PDF уже записывает только свойства файла.
- Не вводится автосохранение условий: это отдельное продуктовое решение и не нужно для устранения потери черновика.
- Browser-smoke зависит от локальной авторизации и тестовых данных; при недоступности будет явно зафиксирован как непроведённый.
