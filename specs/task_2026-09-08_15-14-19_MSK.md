# Bitrix #21924 — количество автомобиля выше складского остатка

**Задача:** https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/21924/

## Текущее поведение

На странице корзины компонент `frontend/features/cart/components/CartItemCard.vue` получает `maxQuantity`, рассчитанное по фактическому складскому остатку автомобиля. Это значение используется как HTML-ограничение `max` у поля количества и в наблюдателе, который после загрузки остатков принудительно уменьшает уже указанное количество.

Поэтому стрелки numeric-input не позволяют увеличить количество выше остатка. Ручной ввод значения выше остатка уже сохраняет это значение и запускает пересчёт калькулятора, однако пользователь получает непоследовательное поведение.

На скриншоте: для автомобиля доступен 1 экземпляр, а пользователь указал 3; расчёт корректно учитывает 3, но стрелки не позволяют получить то же значение.

## Целевое поведение и причина

Для обычного автомобиля в корзине (`item.ref.type === 'vehicle'`) дилер может указать любое целое количество не меньше 1 — и вручную, и кнопками numeric-input. Количество выше текущего остатка означает, что дилер готов докупить транспорт специально под заявку.

Складской остаток сохраняется в интерфейсе как справочная подпись `Доступно: N`, но перестаёт быть верхней границей количества автомобиля. Калькулятор и данные корзины должны использовать указанное пользователем количество.

Спецтехника (`special_equipment`) не входит в эту задачу: для неё действующее ограничение остатком остаётся без изменений.

## Выбранный подход

Разделить понятия «справочный складской остаток» и «максимально разрешённое количество» в общей карточке корзины:

- передавать в карточку доступное количество как отдельное значение для отображения;
- для автомобиля не передавать HTML-атрибут `max` и не применять принудительное уменьшение значения при обновлении остатков;
- для спецтехники сохранить текущие `max` и защиту от значения выше остатка;
- не менять API, расчёт лизинга, типы идентификаторов, цену, выбор карточки и отправку заявки.

### Альтернативы и риски

- **Убрать ограничение для всех строк корзины.** Отклонено: это изменит правила спецтехники без требования задачи.
- **Оставить `max`, но обходить его только при ручном вводе.** Отклонено: сохраняет описанную пользователем непоследовательность кнопок и ввода.
- **Изменить backend-валидацию.** Не требуется: ручной ввод уже принимается и используется калькулятором. Риск остаётся только в возможной серверной валидации на этапе отправки заявки; текущая задача не меняет этот контракт.

## Планируемые изменения

1. В `frontend/features/cart/components/CartItemCard.vue` отделить отображаемый остаток от ограничения количества.
2. Для строки автомобиля убрать верхнюю границу numeric-input и watcher, уменьшающий значение до остатка.
3. Для строки спецтехники оставить ограничение `max` и текущую защиту от превышения остатка.
4. В `frontend/pages/cart/index.vue` передавать остаток в карточку без обозначения его как общего максимума.
5. Добавить регрессионный архитектурный тест, проверяющий оба правила: неограниченное количество автомобиля и сохранённую границу для спецтехники.

## Критерии готовности

1. В корзине с автомобилем, для которого показано `Доступно: 1`, можно стрелками увеличить количество с 1 до 3 без ошибки и без возврата к 1.
2. В том же поле можно вручную ввести 3; после потери фокуса значение остаётся 3.
3. При обновлении сведений об остатках автомобиль с количеством выше остатка не уменьшается автоматически.
4. Калькулятор получает пользовательское количество и пересчитывает итог для него.
5. Подпись `Доступно: N` для автомобиля остаётся видимой, когда остаток известен.
6. Для спецтехники количество по-прежнему не может превысить доступный остаток.
7. Изменение не затрагивает цену, допоборудование, допуслуги, комментарий, удаление из корзины и API-запросы.
8. Новый регрессионный тест проходит; полный `bun run test:arch` и production-сборка фронтенда проходят без новых ошибок.
