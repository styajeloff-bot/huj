# Полный фактический путь в HTTP-логах

## Постановка

Текущий HTTP summary сокращает совпавшие маршруты до относительного шаблона
вроде `/{application_id}` или `/`, а часть успешно обработанных запросов
помечает как `/{unmatched}`. По такой записи нельзя понять, к какому API-пути
относился запрос.

Нужно выводить в каждой HTTP-строке фактический полный path запроса, начиная с
`/api/...`, без шаблонов `{application_id}`, `{item_id}`, значения
`/{unmatched}` и других сокращений.

## Требования

- `http_route` содержит `request.url.path` целиком, включая фактические UUID и
  другие path-параметры.
- Человекочитаемое поле `message` содержит тот же полный path.
- Query string и fragment в лог не попадают.
- Существующая централизованная маскировка секретов продолжает применяться к
  пути; известные токены, секреты и ИНН в `/api/v1/accounting/{inn}` не должны
  появляться в выводе.
- Обычные, параметризованные, отсутствующие, CORS/CSRF и внутренне
  нормализованные по завершающему слешу запросы используют одно правило без
  специальных значений `/{unmatched}`.
- Поля `request_id`, `correlation_id`, HTTP method, status и duration сохраняют
  текущий контракт.
- Изменение не добавляет path или идентификаторы в индексируемые Loki labels.

## Планируемые изменения

- Упростить `RequestTimingMiddleware`: формировать HTTP path непосредственно из
  `request.url.path` и удалить определение route template/fallback.
- Обновить тесты HTTP-логирования для полного фактического пути, отсутствия
  query string и одинакового поведения на ранних ответах и 404.
- Добавить регрессионный сценарий для маршрута с prefix и path-параметрами, а
  также для внутренней нормализации завершающего `/`.
- Расширить централизованную маскировку для ИНН в accounting path, сохранив
  полный фактический путь для обычных идентификаторов.
- Проверить итоговую строку локальным HTTP-запросом через Nginx и просмотреть
  JSON-лог backend.

## Критерии готовности

- Запрос к параметризованному endpoint пишет полный фактический путь, например
  `/api/v1/dealer/leasing-applications/<uuid>/items/<uuid>/price`.
- Запрос с несовпадающим завершающим `/` пишет фактически запрошенный полный
  path и не пишет `/{unmatched}`.
- Настоящий 404 пишет фактически запрошенный полный path и не пишет
  `/{unmatched}`.
- В HTTP summary отсутствуют query values, cookies, authorization headers и
  известные секреты.
- Узкие регрессионные тесты, Ruff, import-linter, mypy и полный pytest проходят.
- Backend собран и перезапущен в Docker; локальный HTTP replay подтверждает
  ожидаемый JSON.
- Изменение доставлено отдельным MR в `test`, спецификация переименована в номер
  MR, обязательный review пройден, MR автоматически слит.
