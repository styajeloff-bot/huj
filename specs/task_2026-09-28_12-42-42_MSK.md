## 1. Постановка задачи

### Текущее поведение
На странице объявления (`SpecialEquipmentProductPage.vue`) логические характеристики (`data_type = 'boolean'`) во всех блоках выводятся одинаково — через `presentSpecialEquipmentDetailAttribute` (`attributeDisplay.ts`):

| Значение | Что видит посетитель |
|---|---|
| `true` | строка с названием характеристики, значение пустое (для скринридера — скрытое «выбрано») |
| `false` | строка не выводится |

Так работают три блока:

| Блок | Источник данных | Функция на фронтенде |
|---|---|---|
| «Ключевые характеристики» (справа под ценой) | `card_attributes` (модификация) | `presentSpecialEquipmentDetailAttribute` напрямую |
| «Характеристики модификации» (внизу) | `component_blocks` (модификация базовой техники и надстроек) | `displayableSpecialEquipmentComponentBlocks` → `presentSpecialEquipmentDetailAttribute` |
| «Параметры комплектации» | `trim_attribute_groups` (комплектация) | `displayableSpecialEquipmentAttributeGroups` → `presentSpecialEquipmentDetailAttribute` |

Backend уже отдаёт в `component_blocks` логические значения обоих видов (`value: true` и `value: false`) — значение «Нет» хранится в `value_boolean = false` и не отбрасывается в `_attribute_resource` / `_component_groups_resource`. То есть скрытие «Нет» — чисто фронтендовое правило.

### Требуемое поведение
Только в блоке **«Характеристики модификации»** (все его подблоки: базовая техника и надстройки составного объявления):

| Значение | Что видит посетитель |
|---|---|
| `true` | название характеристики + значение **«Да»** |
| `false` | название характеристики + значение **«Нет»** |
| значение отсутствует / не `boolean` (`null`, строка и т. п.) | строка не выводится (как сейчас для некорректных значений) |

Без изменений:
- **«Параметры комплектации»** — как сейчас: `true` → только название, `false` → скрыт.
- **«Ключевые характеристики»** — как сейчас: `true` → только название, `false` → скрыт.
- **Карточки в листинге каталога** (`SpecialEquipmentProductCard.vue`) — как сейчас (выводят `display_value`, где уже «Да»/«Нет»).
- Небулевы характеристики (число, текст, список) — форматирование без изменений.
- Порядок групп и характеристик, заголовки блоков, подписи «Базовая техника: …» / «Надстройка: …».

### Связь с другими задачами
Задача независима по коду от `specs/task_2026-09-28_10-34-59_MSK.md` («показывать все характеристики модификации»): та меняет только backend (состав `component_blocks`), эта — только фронтенд (отображение). Файлы не пересекаются, порядок мержа любой.

Эффект на стенде: пока та задача не выполнена, в блоке «Характеристики модификации» выводятся только характеристики с «В карточке» = Да, поэтому «Да»/«Нет» будет видно только у таких логических характеристик. После неё — у всех логических характеристик модификации.

## 2. Требования к реализации

### 2.1. `attributeDisplay.ts` — новая функция для характеристик модификации
Добавить экспортируемую функцию рядом с `presentSpecialEquipmentDetailAttribute` (ту **не менять**, её используют «Ключевые характеристики» и «Параметры комплектации»):

```ts
export const presentSpecialEquipmentModificationAttribute = <T extends SpecialEquipmentDetailAttribute>(
  attribute: T,
): (T & { formatted_value: string | null }) | null => {
  if (attribute.data_type === 'boolean') {
    if (attribute.value === true) return { ...attribute, formatted_value: 'Да' }
    if (attribute.value === false) return { ...attribute, formatted_value: 'Нет' }
    return null
  }
  return presentSpecialEquipmentDetailAttribute(attribute)
}
```

Правила безопасности:
- Сравнение строгое (`=== true` / `=== false`). Строки `'true'`, `'false'`, `'Да'` и т. п. не интерпретируются: контракт `component_blocks` отдаёт `boolean`, а неожиданный тип не должен превращаться в «Нет».
- Тексты «Да» / «Нет» — те же, что уже используются в `formatSpecialEquipmentAttribute` и в backend `format_attribute_display_value`; единицу измерения к ним не добавлять.
- Тип возвращаемого значения совместим с текущим: `formatted_value: string | null`, шаблон менять не нужно.

### 2.2. `componentBlockPresentation.ts`
В `displayableSpecialEquipmentComponentBlocks` заменить вызов `presentSpecialEquipmentDetailAttribute` на `presentSpecialEquipmentModificationAttribute`. Остальная логика (отбрасывание пустых групп и блоков, `display_name`, `source_caption`) не меняется.

Следствие: группа, в которой были только логические характеристики со значением `false`, раньше скрывалась целиком, а теперь выводится (со строками «Нет»). Это ожидаемое поведение.

### 2.3. `SpecialEquipmentProductPage.vue`
Изменений не требуется:
- в шаблоне блока `equipment.detail.specs` уже есть `<dd v-if="attribute.formatted_value !== null">…`, строки получат значение «Да»/«Нет» и выровняются так же, как числовые;
- ветка `<dd v-else class="sr-only">выбрано</dd>` остаётся (она нужна для «Параметров комплектации» и «Ключевых характеристик»);
- `cardAttributes` и `trimAttributeGroups` продолжают использовать прежние функции.

### 2.4. Что не меняется
- Backend, схемы ответа API, БД, миграции, импорт, админка.
- `presentSpecialEquipmentDetailAttribute`, `formatSpecialEquipmentAttribute`, `displayableSpecialEquipmentAttributeGroups`.
- Фильтры и фасеты каталога.
- Правила desktop-only (ширина ≥ 768 px) — новая вёрстка не добавляется.
