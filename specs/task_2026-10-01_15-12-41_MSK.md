## 1. Контекст и текущая проблема

В рамках задачи Bitrix #22282 ранее была реализована логика отображения ленты шагов на странице лизинговой заявки (`frontend/pages/application/[id].vue`). При переходе на следующий шаг предыдущие шаги отмечались галочкой вместо цифры и окрашивались в серый цвет (`completed`), а текущий шаг подсвечивался синим цветом с номером (`current`).

Однако функция `stepState` вычисляла состояние относительно текущего шага:
```ts
const stepState = (section: CheckoutSection): StepState => {
  const currentIndex = visibleCheckoutSteps.value.findIndex(step => step.section === currentSection.value)
  const index = visibleCheckoutSteps.value.findIndex(step => step.section === section)
  if (index === currentIndex) return 'current'
  return index < currentIndex ? 'completed' : 'upcoming'
}
```

**Проблема:**
Если пользователь продвинулся по процессу оформления (например, до шага 4 «Предварительные» или шага 5 «Итоговое»), а затем перешёл назад на один из предыдущих шагов (например, на шаг 2 «О компании» или шаг 1 «Анкета»), то шаги, расположенные после выбранного шага (например, шаг 3 «Отправленные», шаг 4 «Предварительные»), имеют `index > currentIndex` и снова возвращаются в состояние `upcoming` (становятся серыми с цифрами вместо галочек).

## 2. Целевое поведение

1. Если пользователь уже прошёл шаг (перешёл на следующий шаг процесса или заявка находится на соответствующем статусном этапе), этот шаг считается пройденным (`completed`) и отображается серым цветом с галочкой вместо цифры.
2. При возврате пользователя на любой из предыдущих шагов:
   - Шаг, на котором сейчас находится пользователь, **всегда подсвечивается синим** (`current`), отображает свой номер и активную обводку (`ring-4`).
   - Уже пройденные шаги (как до, так и после текущего шага) **не меняются на цифры** и сохраняют галочки (`completed`).
   - Ещё не достигнутые будущие шаги (и недоступные статусные шаги) отображаются с цифрами (`upcoming`).
3. При переходе с шага назад и последующем возврате вперёд на ранее достигнутый шаг лента корректно переключает синюю подсветку на активный шаг, а предыдущий остаётся с галочкой.

## 3. Границы задачи

### Входит в задачу
- Корректировка вычисления состояния шагов `stepState` в `frontend/pages/application/[id].vue` с учётом максимального достигнутого шага (`maxReachedStepIndex`).
- Поддержка сохранения пройденного состояния шагов при переходах назад/вперёд по ленте и кнопкам навигации.
- Сохранение правил доступности переходов `canJump()`.
- Добавление сквозных E2E-тестов Playwright в `frontend/tests/e2e/checkout/22282-auto-switch-status-steps.spec.ts` для проверки переходов назад из статусных этапов (шаг 4 и шаг 5) на шаги 1 и 2.

### Не входит в задачу
- Изменение состава, порядка или именования шагов в `frontend/features/checkout/utils/steps.ts`.
- Изменение backend API, схем БД, моделей или миграций (задача чисто фронтендовая).
- Мобильная адаптация для ширины экрана менее 768 CSS-пикселей.

## 4. Техническое решение

1. В `frontend/pages/application/[id].vue` ввести реактивную переменную максимального достигнутого индекса шага:
   ```ts
   const maxReachedStepIndex = ref(0)
   ```
2. Реализовать функцию фиксации максимального достигнутого шага `updateMaxReachedStep(section: CheckoutSection)`:
   - Находит индекс `section` в `visibleCheckoutSteps`.
   - Если найденный индекс больше `maxReachedStepIndex.value`, обновляет `maxReachedStepIndex.value = index`.
3. Зафиксировать отслеживание изменений `currentSection` (через `watch(currentSection, ...)` и явные вызовы в `setSection` и `onMounted`), чтобы при любом переходе вперёд максимальный индекс увеличивался.
4. Обновить функцию `stepState`:
   ```ts
   type StepState = 'current' | 'completed' | 'upcoming'
   const stepState = (section: CheckoutSection): StepState => {
     const currentIndex = visibleCheckoutSteps.value.findIndex(step => step.section === currentSection.value)
     const index = visibleCheckoutSteps.value.findIndex(step => step.section === section)
     if (index === currentIndex) return 'current'
     if (isCheckoutStatusSection(section) && !isSectionAvailable(section)) return 'upcoming'
     if (index >= 0 && index < maxReachedStepIndex.value) return 'completed'
     return 'upcoming'
   }
   ```
5. В `canJump(section)` обеспечить возможность перехода на любой шаг в пределах достигнутого диапазона:
   ```ts
   const canJump = (section: CheckoutSection) => {
     if (isCheckoutStatusSection(section)) return isSectionAvailable(section)
     if (isClientCheckoutLocked.value) return section === 'questionnaire' || section === 'company'
     const index = visibleCheckoutSteps.value.findIndex(step => step.section === section)
     return index <= maxReachedStepIndex.value || checkoutStepForSection(section) <= maxReachedStep.value
   }
   ```
