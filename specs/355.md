## Текущее поведение

На странице `/cart/conditions` пользователь выбирает компанию в `CheckoutConditions.vue`. Выбранный UUID сохраняется в `checkoutStore.selectedCompanyId`, но на странице отображаются только техника и условия лизинга.

Отчёт о компании на этом этапе не выводится. Сообщение о необходимости загрузить банковские выписки относится к отдельному dashboard по транзакциям и не является отчётом ФНС.

Полный отчёт ФНС уже реализован на шаге 2 заявки в `CheckoutCompanyData.vue`. Он загружает профиль выбранной компании по UUID и бухгалтерскую отчётность по ИНН через существующий защищённый API:

- `GET /api/v1/companies/{company_id}/profile`;
- `GET /api/v1/accounting/{inn}`;
- `POST /api/v1/accounting/{inn}/refresh`.

Компонент выводит реквизиты и статус компании, доступные годы, KPI, графики, бухгалтерские формы, коэффициенты и ссылки на опубликованные файлы. API уже определяет 404 как отсутствие опубликованной ФНС отчётности и 503 как временную недоступность провайдера.

## Требуемое поведение

После выбора компании на странице создания заявки `/cart/conditions` пользователь видит тот же отчёт ФНС / бухгалтерской отчётности, что и на шаге 2 созданной заявки:

1. Пока компания не выбрана, отчёт не отображается.
2. После выбора сохранённой компании отображается полный `CheckoutCompanyData` с профилем, вкладками и отчётом ФНС.
3. Отчёт строится по ИНН выбранной компании, используя существующий API и его кеш. Новый API, загрузка банковских выписок и новая модель данных не требуются.
4. Для этого раннего экрана не передаётся налоговый режим анкеты: отчёт ФНС отображается для любой выбранной компании и не подменяется dashboard банковских выписок.
5. Если ФНС не публикует данные, уже существующее нейтральное состояние сообщает, что отчётность недоступна для новой организации или ИП; пользователь всё равно может создать заявку.
6. При временной недоступности провайдера или иной ошибке используется существующее безопасное сообщение и кнопка повторной загрузки. Создание заявки не блокируется.
7. При смене выбранной компании прежний отчёт заменяется данными новой компании; при снятии выбора отчёт исчезает.

## Дополнение: порядок экранов для транспортных средств

### Текущее поведение

На `/cart/conditions` `CheckoutConditions.vue` одновременно отображает выбор компании и карточки транспорта с полями «Цель приобретения» и «Регион». Из-за этого карточки показаны до создания заявки — на одном экране с ранним отчётом ФНС.

В проекте уже есть специальный следующий шаг `/application/<id>?step=items`: `ApplicationItemsStep.vue` показывает те же позиции, цель приобретения, регионы и комментарий, а затем сохраняет их через существующий `updateApplicationItems` API.

### Требуемое поведение

1. `/cart/conditions` показывает выбор компании, условия лизинга и ранний отчёт ФНС, но не показывает транспортные средства и их поля.
2. После создания заявки любой путь из `/cart/conditions` направляет пользователя на `/application/<id>?step=items`.
3. На `?step=items` пользователь видит все позиции созданной заявки, заполняет цель приобретения и регионы, сохраняет данные и попадает на шаг анкеты (`?step=1`).
4. Повторно не создавать компонент, API или модель: использовать `ApplicationItemsStep.vue` и существующий API сохранения позиций.
5. Функции создания заявки, выбор компании и ранний отчёт ФНС сохраняют текущее поведение.

### План реализации

1. Ввести в `CheckoutConditions.vue` явный режим без позиций транспорта для предварительного экрана; оставить в нём только выбор компании и блок условий.
2. В `pages/cart/conditions.vue` включить этот режим и убрать зависимость от проверки полей транспорта, которые теперь заполняются на следующем шаге.
3. Во всех ветках успешного создания заявки из `pages/cart/conditions.vue` изменить переход с `?step=1` на `?step=items`.
4. Добавить регрессионные архитектурные тесты: на `/cart/conditions` нет блока позиций; создание заявки отправляет на `?step=items`; `ApplicationItemsStep` остаётся владельцем полей цели и региона.
5. Запустить целевые и связанные frontend-тесты, production build и доступный Docker/browser smoke.

### Критерии приёмки дополнения

- На `/cart/conditions` после выбора ООО «КАРКАДЕ» не видны «Транспортные средства в заявке», «Цель приобретения» и «Регион».
- Ранний отчёт ФНС по выбранной компании продолжает отображаться на этом же экране.
- После создания заявки пользователь открывает `/application/<id>?step=items` и видит там весь состав транспорта.
- На следующем шаге можно сохранить цель и регионы, после чего открывается анкета.
- Изменение не требует backend/API-работ и не ломает варианты создания заявки для автомобилей, спецтехники и commerce-позиций.

## Бизнес-цель

До создания заявки пользователь должен оценить финансовое состояние выбранной компании по открытой бухгалтерской отчётности. Это уменьшает риск отправки заявки с неверно выбранной компанией и не заставляет пользователя сначала создавать заявку или загружать конфиденциальные банковские выписки ради просмотра публичных данных.

## Планируемые изменения

1. В `frontend/pages/cart/conditions.vue` импортировать существующий `CheckoutCompanyData.vue` и разместить его после `CheckoutConditions` и блока условий лизинга.
2. Рендерить компонент только при непустом `checkoutStore.selectedCompanyId`, передавать выбранный UUID как `company-id`.
3. Не передавать `tax-system`: это сохраняет режим отчёта ФНС и предотвращает переключение в analytics по банковским выпискам, так как анкета ещё не заполнена.
4. Не изменять backend: маршруты отчётности, кеширование, авторизацию, модели и контракт API уже покрывают этот сценарий.
5. Добавить архитектурный регрессионный тест, который фиксирует импорт компонента на `/cart/conditions`, условный рендер только после выбора UUID и отсутствие `tax-system`/bank-statement-ветки на раннем экране.
6. Выполнить проверку frontend-тестов, production build и browser-smoke в Docker: выбрать компанию с данными, проверить полный отчёт; выбрать компанию без данных ФНС, проверить нейтральное состояние и возможность создать заявку.

## Критерии приёмки

- После выбора ООО «КАРКАДЕ» с ИНН `3905019765` на `/cart/conditions` отображается отчёт с заголовком компании, вкладкой «Бухгалтерская отчётность», годами, KPI, графиками и сворачиваемыми формами, как на шаге 2 созданной заявки.
- До выбора компании отчёта на странице нет.

- Для компании, по которой ФНС не публикует отчётность, отображается понятное нейтральное сообщение; кнопка «Создать заявку» остаётся доступной при остальных корректных условиях.
- Для временной ошибки провайдера пользователь видит существующее безопасное сообщение и может повторить загрузку; создание заявки не блокируется.
- Ранний экран не предлагает загрузить банковские выписки как условие просмотра отчёта ФНС.
- `bun run test:arch` и `bun run build:frontend` проходят.
- В Docker browser-smoke на desktop подтверждает сценарий выбора компании и отсутствие блокировки создания заявки при отсутствии отчётности.

## Риски и ограничения

- Отчёт ФНС может быть большим; его загрузка происходит только после явного выбора компании, а существующий API использует кеш.
- Публичная отчётность и банковские выписки остаются разными источниками: в этой задаче не смешиваются и не заменяют друг друга.
- Полный frontend architecture suite может содержать независимые ранее существовавшие нарушения. Если они проявятся, в отчёте будут отдельно указаны результат изменённого теста и внешние блокеры.
- Блокирующих вопросов нет.
