# Bitrix #21368 — Backspace в маске номера при регистрации

**Задача:** https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/21368/

## Текущее поведение

В `frontend/features/auth/components/AuthModal.vue` поле телефона используется и во входе, и при регистрации. После каждого события `input` функция `formatPhone` удаляет все нецифровые символы и заново собирает строку вида `+7 (777) 777-77-77`.

При удерживании Backspace курсор после переформатирования может остановиться перед символом маски (`-`, пробелом или `)`). Чтобы продолжить удаление номера, пользователю приходится вручную перемещать курсор мышью или клавишами со стрелками.

## Требуемое поведение

В форме регистрации пользователь должен удалять введённый номер клавишей Backspace подряд, без мыши и стрелок:

1. Для номера `+7 (777) 777-77-77` каждое нажатие Backspace удаляет следующую цифру абонентского номера, а не останавливается на символе маски.
2. После удаления десяти цифр абонентского номера в поле остаётся только неизменяемый префикс `+7`; введённый пользователем номер полностью очищен.
3. Курсор остаётся в позиции, из которой следующее нажатие Backspace снова удалит предыдущую цифру, если она есть.
4. Ввод цифр, формат `+7 (XXX) XXX-XX-XX`, ограничение длины, нормализация начальной `8` в `7` и валидация номера сохраняют текущее поведение.
5. Поле входа использует тот же обработчик, поэтому получает то же корректное поведение без отдельной дублирующей реализации.

## Зачем это нужно

Номер телефона — обязательное поле регистрации. Пользователь должен иметь возможность исправить или полностью очистить ошибочно введённый номер стандартной клавишей Backspace. Принудительное ручное перемещение курсора делает регистрацию ненадёжной и создаёт риск отказа от формы.

## Подход и границы

Выбран frontend-only подход с явной обработкой Backspace и сохранением позиции курсора.

1. Вынести операции маски телефона из `AuthModal.vue` в небольшую чистую функцию в `frontend/features/auth/`.
2. Функция получает текущее значение поля и позицию курсора, определяет предыдущую цифру абонентского номера, удаляет только её и возвращает заново отформатированное значение вместе с новой позицией курсора.
3. В `AuthModal.vue` добавить обработчик клавиши Backspace для телефонного поля. Он применяет функцию только когда требуется пропустить символ маски; обычный ввод и выделение текста продолжают обрабатываться существующим полем и форматированием.
4. После обновления реактивного значения восстанавливать вычисленную позицию курсора в следующем цикле рендеринга, чтобы Vue не переносил её в конец поля.
5. Backend, API-запросы, данные пользователя, SMS-подтверждение и остальные поля формы не меняются.

## Альтернативы и риски

- Полностью заменить поле сторонней библиотекой масок: не выбрано, потому что это добавит зависимость и затронет ввод телефона шире задачи.
- Оставить только `@input` и пытаться угадать позицию по отформатированной строке: не выбрано, потому что обработчик не знает, удалил ли браузер цифру или разделитель.
- Риск: Backspace при выделенном фрагменте может требовать отдельной логики. В реализации выделенный диапазон не будет обрабатываться как одиночное удаление: сохраняется ожидаемое нативное удаление выделенного текста с последующим форматированием.
- Риск: исходный `+7` является системным префиксом. После удаления всех абонентских цифр он остаётся в поле и не считается заполненным номером; существующая валидация по 11 цифрам продолжает блокировать отправку.

## План реализации

1. Создать `frontend/tests/architecture/auth-phone-mask-21368.test.ts` с регрессиями маски:
   - последовательное удаление цифр из полного номера через Backspace;
   - переход через оба дефиса, пробел и закрывающую скобку без остановки;
   - итоговое значение `+7` после удаления всех десяти абонентских цифр;
   - корректная позиция курсора после каждого удаления;
   - сохранение форматирования при обычном вводе и нормализации номера, начатого с `8`.
2. Добавить чистую утилиту маски в `frontend/features/auth/` с преобразованием значения и расчётом позиции курсора для Backspace.
3. Изменить `frontend/features/auth/components/AuthModal.vue`:
   - использовать утилиту для текущего форматирования;
   - подключить обработчик Backspace к единственному телефонному input;
   - восстанавливать рассчитанную позицию курсора после реактивного обновления;
   - не менять отправку номера, валидацию, шаги регистрации и входа.
4. Проверить целевой тест, полный набор `bun run test:arch`, production-сборку фронтенда и `git diff --check`.
5. Запустить собранный frontend локально и проверить в браузере desktop-сценарий: в форме регистрации ввести `+7 (777) 777-77-77`, удерживать Backspace до `+7`, затем повторно ввести номер; проверить консоль браузера на ошибки.
6. После успешных проверок закоммитить только файлы задачи, запушить `bugfix/21368`, создать MR строго в `test` и переименовать спецификацию в `specs/<номер-MR>.md`.

## Критерии приёмки

- На форме регистрации номер `+7 (777) 777-77-77` удаляется удерживанием Backspace до состояния `+7` без использования мыши и стрелок.
- Backspace не останавливается у `-`, пробела и `)`.
- После полного удаления абонентских цифр отправка формы не проходит валидацию как для неполного номера.
- После очистки пользователь может снова ввести 10 цифр, а поле покажет `+7 (777) 777-77-77`.
- Номер, начатый с `8`, по-прежнему нормализуется до российского префикса `+7`.
- Поле входа не теряет способность вводить, редактировать и валидировать номер.
- В API не добавлены и не изменены запросы; backend-файлы не меняются.
- Все новые регрессионные тесты, `bun run test:arch`, production-сборка и проверка без пробельных ошибок проходят успешно.

## Вопросы

Блокирующих вопросов нет. Задача ограничена телефоном в `AuthModal.vue`; другие телефонные поля анкеты и профилей в эту задачу не входят.
