# Исправление отображения названия склада после возврата в каталог

## Контекст

- Bitrix: https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/22140/
- Экран: публичный каталог автомобилей `/cars`, режим «Выбрать автомобиль по специальной цене».
- Сценарий: пользователь выбирает склад, открывает страницу автомобиля, затем возвращается кнопкой браузера в каталог.

## Текущее поведение

Выбор склада и UUID сохраняются в локальном хранилище фильтров. После возврата страница восстанавливает UUID склада, но справочник складов ещё не загружен. Компонент формирования активных фильтров не находит склад по UUID и выводит запасной технический текст вида `Склад: f25afdc8-…`.

Причина в текущем порядке загрузки:

- быстрый старт каталога намеренно не загружает тяжёлый справочник складов;
- отложенная загрузка базовых фильтров также исключает склады;
- склад загружается только при открытии связанного фильтра, поэтому активный чип после возврата может остаться с UUID.

## Целевое поведение и бизнес-результат

Если после возврата в каталог восстановлен фильтр по складу, активный чип должен показывать адрес выбранного склада, а не UUID. Сам фильтр, выдача автомобилей, текущая страница и остальные сохранённые параметры должны сохраняться без изменений.

Это избавляет пользователя от технических идентификаторов и позволяет понять, какой склад остаётся применённым к каталогу.

## Подходы и риски

1. **Рекомендуемый: отложенно загрузить только справочник складов при наличии восстановленного складского фильтра.**
   - Не блокировать первую загрузку списка автомобилей.
   - После восстановления фильтров и первого запроса каталога асинхронно получить список складов только когда в фильтре есть хотя бы один UUID склада.
   - После получения справочника реактивно заменить UUID в чипе на адрес.
   - Риск: до завершения короткого фонового запроса возможен временный технический текст; после успешного ответа он будет заменён без действий пользователя.

2. **Сохранять адрес склада вместе с UUID в локальном хранилище.**
   - Плюс: имя доступно сразу.
   - Риск: адрес может устареть после изменения склада, а структура сохранённых фильтров усложнится. Не рекомендуется.

3. **Заменить UUID в запасном тексте на «1 склад».**
   - Плюс: не показывается техническое значение.
   - Риск: пользователь всё равно не узнаёт выбранный склад. Не решает задачу.

## Планируемые изменения

### Frontend

- `frontend/pages/cars/index.vue`
  - в отложенной инициализации после восстановления фильтров добавить условную загрузку справочника складов, только если выбран хотя бы один склад;
  - сохранить принцип быстрого первого отображения каталога: загрузка автомобилей не должна ожидать справочник складов;
  - не менять формат UUID, URL маршрута, сохранение фильтров и API-запрос выдачи автомобилей.

- `frontend/tests/architecture/`
  - добавить регрессионную проверку контракта восстановления складского фильтра;
  - подтвердить, что при сохранённом UUID склада страница планирует загрузить справочник складов, а активный чип использует адрес склада;
  - подтвердить, что первая загрузка автомобилей по-прежнему не блокируется ожиданием справочника складов.

## Критерии готовности

- После выбора склада, открытия карточки автомобиля и возврата браузером в каталог активный чип показывает `Склад: <адрес склада>`, а не UUID.
- Складской UUID остаётся непрозрачной строкой: без числовых преобразований и подмены идентификатора.
- Если склад не выбран, дополнительный запрос справочника складов при восстановлении фильтров не выполняется.
- Первая загрузка каталога автомобилей не ожидает загрузку справочника складов.
- Выдача остаётся отфильтрованной тем же выбранным складом; сброс фильтра и переход между режимами каталога не меняются.
- Пройдут новый точечный frontend-тест, полный `bun run test:arch`, production build и локальная проверка в браузере/DOM, если доступ к авторизованному сценарию возможен.
- MR будет создан из `bugfix/22140` только в `test` и будет содержать ссылку на Bitrix #22140.

## Вопросы и границы

- Блокирующих вопросов нет: симптом, причина и минимальный путь исправления определены.
- Неблокирующий случай: если сохранённый склад был удалён или больше недоступен пользователю, интерфейс сохранит безопасное запасное представление до обновления/сброса фильтра; задача не меняет права доступа и не восстанавливает удалённые склады.
- В задачу не входят изменения backend API, миграции, изменение данных складов, изменение механизма хранения фильтров или рефакторинг всей загрузки фасетов.
