# Настройки оформления витрин и управление шрифтами

## Контекст

- Внутренняя задача, не связанная с Bitrix.
- Источник требований — постановка пользователя от 08.09.2026 и актуальный
  `origin/test` на коммите `6afffae50fb0d684d96746a8e549b4719b727d79`.
- В workspace администратора уже есть раздел «Витрины». В нём можно выбрать
  основную или дополнительную витрину и отдельно изменить основные настройки,
  публичные страницы и видимость.
- Публичная конфигурация витрины загружается через
  `GET /api/v1/storefront` или `GET /api/v1/storefronts/{storefront_slug}` до
  отображения страницы. Это существующая точка доставки настроек оформления в
  SSR и клиентскую гидрацию.
- Сейчас шрифт `Mulish`, основные цвета и значения `border-radius`
  захардкожены во frontend. Загружаемого общего каталога шрифтов нет.
- Актуальная Alembic-ветка имеет единственную голову `112`.

## Как понята задача

Администратор должен управлять внешним видом каждой публичной витрины из
существующего раздела workspace «Витрины»:

1. Для конкретной витрины выбрать основные цвета, единый масштаб скруглений и
   шрифт.
2. В общем для всех витрин разделе «Шрифты» загрузить файл шрифта с названием и
   описанием, увидеть список загруженных шрифтов, переименовать их, изменить
   описание или удалить.
3. В настройках конкретной витрины выбрать один из загруженных шрифтов через
   `select` либо оставить системный шрифт по умолчанию.
4. Настройки одной витрины не должны менять другую витрину и не должны менять
   оформление административного workspace.

В рамках этой задачи «цвета» означают четыре семантических цвета витрины:

| Настройка | Назначение | Значение по умолчанию |
| --- | --- | --- |
| Основной цвет | кнопки, ссылки, активная навигация, focus-ring и брендовые акценты | `#3367BD` |
| Фон страницы | общий фон публичной части | `#F9FAFB` |
| Фон поверхностей | карточки, формы, меню, модальные окна | `#FFFFFF` |
| Основной текст | заголовки и основной текст | `#111827` |

Оттенки hover, muted, border и цвет текста на основном фоне вычисляются из этих
значений как производные токены. Цвета ошибок, предупреждений, успеха, статусов
сущностей и графиков не являются брендовыми и этой настройкой не меняются.

## Цель и бизнес-результат

Каждая витрина получает самостоятельное, реально применяемое оформление без
доработки исходного кода под новый бренд. Администратор загружает разрешённый
шрифт один раз, после чего может использовать его в одной или нескольких
витринах. Публичный пользователь сразу при первом SSR-ответе видит правильные
цвета, скругления и шрифт своей витрины без мигания значений другой витрины.

## Термины и границы

- **Каталог шрифтов** — общий для всех витрин набор загруженных администратором
  файлов и их метаданных.
- **Системный шрифт** — текущий `Mulish` с существующим безопасным системным
  fallback stack. Он всегда доступен, не хранится как пользовательская запись и
  не может быть удалён.
- **Оформление витрины** — цвета, preset скруглений и ссылка на запись каталога
  шрифтов.
- Настройки применяются ко всем пользовательским страницам текущей витрины,
  которые используют публичный `default` layout, включая каталог, карточки,
  корзину, авторизацию и оформление заявки.
- Настройки не применяются к `workspace` layout, административным формам,
  письмам, PDF, печатным формам и содержимому внешних файлов.
- Поддерживается только desktop web с viewport от 768 CSS-пикселей. Отдельная
  mobile-версия и настройки для разных breakpoints не создаются.
- Один элемент каталога содержит один файл шрифта. Наборы из нескольких файлов
  для отдельных начертаний и ручная настройка `font-weight`/`font-style` не
  входят в эту задачу; при отсутствии начертания браузер использует синтез или
  fallback.

## Функциональные требования

### 1. Структура раздела «Витрины»

- На странице `/workspace/storefronts` появляются два верхнеуровневых раздела:
  «Витрины» и «Шрифты».
- Раздел «Витрины» сохраняет существующий список витрин и создание витрины.
- У выбранной существующей витрины появляется внутренняя вкладка «Оформление»
  рядом с «Основные настройки» и «Страницы и видимость».
- Раздел «Шрифты» не зависит от выбранной витрины и показывает общий каталог.
- Активный верхнеуровневый раздел и внутренняя вкладка отражаются в query URL,
  чтобы обновление страницы и переход по сохранённой ссылке восстанавливали тот
  же экран.
- Переход между разделами не должен молча сбрасывать введённые, но ещё не
  сохранённые данные. При попытке уйти с dirty-формы требуется подтверждение.
- Все асинхронные области имеют отдельные loading, empty, error/retry и success
  состояния без блокировки всей страницы из-за одной операции.

### 2. Форма оформления конкретной витрины

- Во вкладке «Оформление» есть четыре подписанных color-поля из таблицы выше.
- Каждое color-поле содержит доступный native color picker и синхронное текстовое
  поле с точным значением `#RRGGBB`; цвет не является единственным способом
  понять выбранное значение.
- Сервер принимает только непрозрачный шестизначный hex без alpha-канала,
  нормализует его к верхнему регистру и возвращает нормализованное значение.
- Основной текст должен иметь контраст не ниже 4.5:1 с фоном страницы и фоном
  поверхностей. Основной цвет должен иметь контраст не ниже 3:1 с обоими фонами;
  для текста на основном цвете система автоматически выбирает чёрный или белый
  вариант с контрастом не ниже 4.5:1.
- Недопустимая комбинация подсвечивается рядом с конкретным полем, введённые
  значения сохраняются, а сервер возвращает понятную доменную ошибку и не
  сохраняет частичную конфигурацию.
- Скругление выбирается одним `select` со стабильными ключами:

| Ключ | Название в UI | Контролы | Поверхности |
| --- | --- | --- | --- |
| `none` | Без скругления | 0 px | 0 px |
| `small` | Небольшое | 4 px | 8 px |
| `medium` | Стандартное | 8 px | 12 px |
| `large` | Крупное | 12 px | 16 px |

- «Контролы» включают кнопки, input и select; «поверхности» — карточки, панели,
  выпадающие меню и модальные окна. Вложенные элементы используют меньший радиус
  своей шкалы. Аватары, круглые индикаторы, radio и pill/badge с осознанным
  `rounded-full` остаются круглыми.
- Шрифт выбирается одним `select`. Первый постоянный вариант —
  «По умолчанию — Mulish», далее идут загруженные шрифты в алфавитном порядке.
- В option показывается название шрифта; полное описание доступно как текст под
  select для выбранного значения, а не прячется только в tooltip.
- Пустой `font_id` означает системный `Mulish`. Произвольное семейство шрифта или
  URL с клиента передать нельзя.
- Цвета, preset скруглений и шрифт сохраняются одной атомарной операцией. При
  ошибке не должна применяться часть настроек.
- После успешного сохранения актуальная запись витрины и её `version`
  обновляются без обязательной полной перезагрузки workspace.

### 3. Общая панель «Шрифты»

- В верхней части раздела находится форма добавления шрифта:
  - обязательное поле «Название шрифта»;
  - необязательное поле «Описание»;
  - обязательный `input type=file` для одного файла;
  - кнопка «Загрузить шрифт» с устойчивым loading-состоянием.
- Название обрезается по краям, обязательно, содержит от 1 до 120 символов и
  уникально без учёта регистра.
- Описание обрезается по краям, может быть пустым и ограничено 500 символами.
- При ошибке загрузки название, описание и выбранный файл не сбрасываются.
- Под формой показывается список шрифтов, отсортированный по названию без учёта
  регистра. Для каждого элемента видны название, описание или «Без описания»,
  исходное имя файла, размер, дата загрузки и количество использующих витрин.
- Для каждого пользовательского шрифта доступны явные действия
  «Редактировать» и «Удалить». Действия доступны с клавиатуры и не появляются
  только по hover.
- Редактирование меняет название и описание, но не файл. Для замены файла
  создаётся новая запись, после чего витрины переводятся на неё явно.
- Удаление требует подтверждения. Если шрифт выбран в витринах, подтверждение
  показывает их количество и предупреждает, что они перейдут на `Mulish`.
- Удаление отвязывает шрифт от всех использующих его витрин, увеличивает версии
  этих витрин, удаляет запись и файл. Не остаются ссылки на отсутствующий файл.
- Если удаление объекта из хранилища временно не удалось, состояние не должно
  выдаваться за полностью завершённое: операция должна быть безопасно повторяема,
  а ошибка — зафиксирована без раскрытия внутреннего storage key.
- Для пустого каталога показывается объяснение и основное действие загрузки.
- В форме есть пояснение: администратор должен загружать только шрифты, на
  использование которых у компании есть права.

### 4. Проверка и хранение файлов шрифтов

- Поддерживаются входные форматы `.woff2`, `.woff`, `.ttf` и `.otf` размером от
  1 байта до 5 МиБ.
- Расширение и заявленный MIME недостаточны: backend декодирует шрифт библиотекой
  `fontTools`, проверяет структуру и отклоняет повреждённые или не являющиеся
  шрифтами файлы.
- `fontTools` добавляется как прямая backend-зависимость с поддержкой WOFF, а не
  используется случайно как транзитивная зависимость другого пакета.
- Валидный входной файл нормализуется в WOFF2; в object storage сохраняется
  только нормализованный результат под сгенерированным ключом вида
  `storefront-fonts/{font_id}/font.woff2`. Пользовательские имена не участвуют в
  storage key или CSS identifier.
- Для содержимого вычисляется SHA-256. Повторная загрузка тех же байтов
  отклоняется с HTTP 409 и сообщает название существующей записи.
- CSS-family формируется сервером из UUID, например
  `storefront-font-<uuid-without-dashes>`, поэтому переименование не меняет CSS
  и не позволяет внедрить произвольное CSS-значение.
- Один неизменяемый файл доступен публично через FastAPI по UUID. Endpoint
  возвращает `font/woff2`, `X-Content-Type-Options: nosniff`, ETag по SHA-256 и
  `Cache-Control: public, max-age=31536000, immutable`.
- Публичная выдача файла является единственным новым endpoint без JWT; в
  публичный allowlist добавляется только чтение конкретного содержимого шрифта.
  Список, метаданные и все операции изменения остаются admin-only.
- Нельзя получить произвольный объект storage подстановкой пути, имени файла или
  другого идентификатора.

### 5. Независимость витрин и значения по умолчанию

- Для всех существующих витрин миграция устанавливает текущий внешний вид:
  четыре цвета из таблицы, `medium` и системный `Mulish`.
- Миграция не меняет вид уже работающих публичных страниц.
- Новая дочерняя витрина при создании получает независимый снимок оформления
  основной витрины, как уже происходит с `public_ui`. Последующее изменение
  основной витрины не меняет дочернюю и наоборот.
- Пользовательский шрифт остаётся общей записью каталога: несколько витрин могут
  ссылаться на один UUID, но выбор шрифта сохраняется отдельно для каждой.
- Неактивная витрина сохраняет оформление; после повторного включения оно не
  сбрасывается.
- Несуществующий или удалённый `font_id` нельзя сохранить. При ранее выбранном,
  но недоступном файле публичный frontend использует `Mulish`/system fallback и
  остаётся работоспособным.

### 6. Публичное применение темы

- Публичный storefront response содержит эффективное оформление текущей
  витрины. Для выбранного пользовательского шрифта он содержит безопасные
  `font_id`, сгенерированное CSS-family и URL WOFF2-файла; описание в публичный
  ответ не передаётся.
- Значения попадают в существующий storefront store и применяются на корневом
  контейнере `default` layout через семантические CSS variables, например
  `--storefront-primary`, `--storefront-background`,
  `--storefront-surface`, `--storefront-text`,
  `--storefront-radius-control`, `--storefront-radius-surface` и
  `--storefront-font-family`.
- `@font-face` создаётся только для выбранного пользовательского шрифта,
  использует сгенерированное family, `font-display: swap` и fallback
  `Mulish, ui-sans-serif, system-ui, sans-serif`.
- Выбранный шрифт предварительно загружается как единственный WOFF2 resource
  текущей витрины. Ошибка сети или декодирования не блокирует текст и не создаёт
  бесконечных повторов.
- SSR отдаёт те же CSS variables и font-метаданные, что затем использует клиент.
  При гидрации не должно быть смены темы основной витрины на дочернюю, CLS из-за
  позднего применения radius/color или утечки темы между slug-маршрутами.
- При смене контекста витрины старый `@font-face`, preload и CSS variables
  заменяются актуальными, а не накапливаются.
- Существующие публичные компоненты переводятся с брендовых hardcoded blue/gray
  и произвольных `rounded-*` на семантические storefront-токены. Статусные цвета
  и намеренно круглые элементы сохраняют текущую семантику.
- Основной текст и интерактивные элементы остаются различимыми без опоры только
  на цвет. Видимый `focus-visible` обязателен для всех новых контролов.

## API-контракт

### Административный каталог шрифтов

| Метод и путь | Назначение | Ответ |
| --- | --- | --- |
| `GET /api/v1/admin/storefront-fonts` | список шрифтов | `200 { items: [...] }` |
| `POST /api/v1/admin/storefront-fonts` | multipart-загрузка `file`, `name`, `description` | `201`, полный ресурс и `Location` |
| `PATCH /api/v1/admin/storefront-fonts/{font_id}` | изменение `name` и/или `description` | `200`, полный ресурс |
| `DELETE /api/v1/admin/storefront-fonts/{font_id}` | удаление и fallback использующих витрин | `204` |
| `GET /api/v1/storefront-fonts/{font_id}/content` | публичное WOFF2-содержимое | `200` или `304` по ETag |

`font_id` — UUID во всех слоях и непрозрачная строка на frontend. Числовые
преобразования и альтернативные поля идентификатора запрещены.

Ресурс административного списка содержит как минимум:

```json
{
  "id": "uuid",
  "name": "Brand Sans",
  "description": "Основной шрифт бренда",
  "original_filename": "brand-sans.ttf",
  "content_type": "font/woff2",
  "size_bytes": 123456,
  "checksum_sha256": "hex",
  "storefront_usage_count": 2,
  "created_at": "timezone-aware ISO-8601",
  "updated_at": "timezone-aware ISO-8601"
}
```

### Оформление витрины

`PATCH /api/v1/admin/storefronts/{storefront_id}` получает отдельное поле
`appearance`, не смешивая оформление со страницами `public_ui`:

```json
{
  "appearance": {
    "colors": {
      "primary": "#3367BD",
      "background": "#F9FAFB",
      "surface": "#FFFFFF",
      "text": "#111827"
    },
    "border_radius": "medium",
    "font_id": "uuid-or-null"
  }
}
```

Admin response возвращает эти сохранённые значения. Публичный storefront
response возвращает те же colors и `border_radius`, а вместо редактируемых
метаданных — эффективный font descriptor:

```json
{
  "appearance": {
    "colors": {
      "primary": "#3367BD",
      "background": "#F9FAFB",
      "surface": "#FFFFFF",
      "text": "#111827"
    },
    "border_radius": "medium",
    "font": {
      "id": "uuid-or-null",
      "family": "Mulish-or-generated-family",
      "url": "/api/v1/storefront-fonts/{font_id}/content-or-null"
    }
  }
}
```

Любое appearance-обновление валидируется и сохраняется целиком. Неизвестные
ключи запрещены. Ошибки uniqueness/duplicate content возвращаются как 409,
невалидные поля и контраст — как понятная 400/422 ошибка без внутренних деталей.

## Хранение и миграция

### Таблица каталога шрифтов

Добавить `catalog_storefront_fonts`:

- `id UUID PRIMARY KEY`;
- `name VARCHAR(120) NOT NULL` и case-insensitive unique index;
- `description VARCHAR(500) NULL`;
- `original_filename VARCHAR(255) NOT NULL`;
- `storage_key VARCHAR(512) NOT NULL UNIQUE`;
- `content_type VARCHAR(64) NOT NULL`, только `font/woff2`;
- `size_bytes INTEGER NOT NULL` с положительным check;
- `checksum_sha256 CHAR(64) NOT NULL UNIQUE`;
- `created_by UUID NULL REFERENCES users(id) ON DELETE SET NULL`;
- `created_at` и `updated_at` timezone-aware.

### Поля витрины

В `catalog_storefronts` добавить обязательные колонки цветов и preset с
серверными default, а также nullable
`font_id UUID REFERENCES catalog_storefront_fonts(id) ON DELETE SET NULL`.
Database checks ограничивают hex-формат и допустимые ключи `border_radius`.
Контраст остаётся доменным правилом, потому что SQL check для него не должен
дублировать прикладной алгоритм.

Удаление используемого шрифта выполняется application-командой: затронутые
витрины блокируются, получают `font_id=NULL`, увеличенные `version` и
`updated_at`, затем запись шрифта удаляется. Операции с object storage имеют
компенсацию, чтобы не оставлять новый orphan при ошибке БД и не возвращать
успех при неудалённом файле.

## Планируемые изменения

### Backend

1. Создать Alembic-миграцию от головы `112` с таблицей шрифтов, appearance-полями,
   FK, индексами, check constraints и backfill без изменения текущего вида.
2. Расширить domain storefront value objects: семантические цвета, radius preset,
   нормализация hex, contrast guards, font metadata и ошибки каталога.
3. Добавить ORM-модель и репозиторий каталога шрифтов; расширить storefront
   record/repository и независимое копирование appearance при создании витрины.
4. Добавить application queries/commands для списка, загрузки, переименования,
   удаления и выдачи файла с безопасной оркестрацией object storage.
5. Добавить Pydantic-схемы и полные FastAPI endpoints с admin role dependency,
   UUID-контрактом, `response_model`, `summary`, `description` и корректными
   REST status/headers.
6. Расширить публичный и административный storefront response полем
   `appearance`, а PATCH — атомарным appearance request.
7. Добавить публичный content endpoint в точечный auth allowlist и не расширять
   доверие ко всему namespace шрифтов.

### Frontend

1. Расширить storefront types, store, default context и API-адаптер новыми
   appearance/font контрактами без `any` и преобразования UUID.
2. Выделить в admin storefront feature отдельные компоненты верхнего уровня,
   формы «Оформление» и панели «Шрифты», не увеличивая существующий монолитный
   компонент ещё одной несвязанной областью.
3. Реализовать загрузку multipart, список, переименование, изменение описания,
   удаление с usage-предупреждением и независимые состояния операций.
4. Реализовать color inputs, radius select, font select, локальную проверку
   формата/контраста и атомарное сохранение appearance выбранной витрины.
5. Добавить composable/plugin уровня storefront layout для SSR-safe CSS
   variables, `@font-face`, preload, очистки прежней темы и font fallback.
6. В пределах публичного `default` layout перевести брендовые цвета, поверхности,
   текст, focus и скругления на семантические токены. Workspace layout оставить
   с текущей административной темой.
7. Сохранить desktop-only контракт 768+, доступность вкладок, полей, диалогов,
   live-region сообщений и работу при 200% zoom.

## Тесты и проверки

### Backend automated tests

- Доменные тесты hex-нормализации, radius enum, контраста и полного атомарного
  appearance contract.
- Integration tests admin-only списка, `201 + Location`, переименования,
  описания и `204` удаления.
- Тесты UUID-контракта и запрета неизвестного/удалённого `font_id`.
- Загрузка валидных WOFF2/WOFF/TTF/OTF с нормализацией в WOFF2; отклонение
  пустого, повреждённого, подменённого и превышающего 5 МиБ файла.
- Тесты case-insensitive duplicate name и duplicate SHA-256 с HTTP 409.
- Тесты object-storage compensation и безопасного повторения удаления.
- Удаление используемого шрифта переводит все связанные витрины на Mulish и
  увеличивает их version.
- Публичный content endpoint проверяет `200`, `304`, `404`, MIME, ETag,
  `nosniff`, immutable cache и отсутствие произвольного доступа к storage.
- Публичный storefront response содержит эффективное appearance, а новая
  витрина копирует appearance основной как независимый снимок.
- Миграционный тест с актуальной PostgreSQL-схемой подтверждает backfill,
  constraints, FK и единственную Alembic-голову.

### Frontend automated tests

- Architecture/regression tests фиксируют верхнеуровневые разделы «Витрины» и
  «Шрифты», внутреннюю вкладку «Оформление» и разбиение feature-компонентов.
- Проверяется точный UUID/API contract, multipart upload и отсутствие числового
  преобразования идентификаторов.
- Проверяются dirty-state, сохранение введённых данных после ошибки, loading,
  empty, retry и destructive confirmation с usage count.
- Проверяется сериализация четырёх цветов, radius и nullable `font_id` без
  частичных PATCH.
- Проверяется SSR/client theme contract: правильные variables, единственный
  выбранный preload/`@font-face`, cleanup при смене витрины и fallback Mulish.
- Проверяется, что тема ограничена `default` layout и не изменяет workspace.

### Ручная browser-проверка

- В desktop viewport 768, 1024 и 1440 px загрузить шрифт, увидеть его в списке,
  переименовать, изменить описание и выбрать в основной витрине.
- Настроить разные цвета, скругления и шрифты минимум у двух витрин; после hard
  reload и прямого перехода по slug убедиться в независимости и отсутствии
  краткого показа темы другой витрины.
- Проверить header, footer, каталог, карточку товара, корзину, авторизацию,
  controls, surfaces и модальное окно; статусы и круглые элементы не должны
  потерять семантику.
- Удалить используемый шрифт после подтверждения и убедиться, что затронутые
  витрины перешли на Mulish без 404/console errors.
- Имитировать недоступный font content: текст сразу остаётся читаемым через
  fallback, страница не блокируется.
- Пройти новые формы только клавиатурой, проверить видимый focus, inline errors,
  live-region сообщения и 200% zoom без горизонтальной прокрутки.

### Обязательные команды перед MR

Backend:

```bash
cd backend
uv run ruff check . --fix
uv run lint-imports
uv run mypy . --ignore-missing-imports
uv run pytest -q
```

Frontend:

```bash
cd frontend
bun run test:arch
bun run build
```

После этого собрать и запустить `backend`, `frontend` и `nginx` в Docker,
проверить health и логи контейнеров, затем выполнить ручные browser-сценарии.

## Критерии готовности

- В «Витринах» есть общий рабочий раздел «Шрифты» с загрузкой файла, названием,
  описанием, списком, переименованием, изменением описания и удалением.
- В каждой витрине есть рабочая вкладка «Оформление» с четырьмя цветами,
  preset скруглений и `select` из общего каталога шрифтов.
- Настройки сохраняются по UUID конкретной витрины и не влияют на другие
  витрины или workspace.
- Существующие витрины после миграции выглядят как до изменения, новые получают
  независимый снимок оформления основной витрины.
- Загруженный файл проверяется по содержимому, нормализуется в WOFF2 и выдаётся
  только через безопасный публичный endpoint с корректным кешированием.
- Удаление используемого шрифта предсказуемо переводит связанные витрины на
  Mulish и не оставляет dangling links или ложного успешного состояния.
- Цвета, скругления и шрифт применяются к публичной витрине с SSR без FOUC/CLS;
  при ошибке шрифта работает fallback.
- Контраст, клавиатурная доступность, focus, loading/error/empty/success состояния
  и desktop-only диапазон 768+ проверены.
- Backend checks, frontend architecture tests/build, Docker-запуск, логи и
  ручные browser-сценарии зелёные.
- Создан MR только в `test`; после создания `specs/temp_4.md` переименован в
  `specs/<номер-MR>.md` в той же ветке.

## Вне объёма задачи

- Несколько font-face файлов внутри одной семьи и отдельный выбор шрифта для
  заголовков и основного текста.
- Ручная настройка font weight, font style, размера, line-height и letter-spacing.
- Произвольные CSS, темы для отдельных страниц/компонентов, gradient, dark mode
  и разные настройки по breakpoints.
- Изменение семантических status colors, графиков, email, PDF, печатных форм и
  административного workspace.
- Импорт Google Fonts по URL, загрузка шрифтов со стороннего origin и публикация
  прямых object-storage URL.
- Мобильная Nuxt-версия для viewport меньше 768 px.
