# Управление видимостью публичной и административной навигации

## Контекст

- Задача является внутренним рефакторингом и не связана с отдельной задачей Bitrix.
- Раздел «Видимость разделов» сейчас управляет только меню рабочих кабинетов
  лизинговых компаний, дилеров и дистрибьюторов.
- Публичный вход в каталог спецтехники и связанные с ним визуальные поверхности
  временно выключены константой `SPECIAL_EQUIPMENT_CATALOG_VISIBLE = false`.
- Страницы модельного ряда доступны по прямым URL `/models*`, но пункт «Модели»
  отсутствует в публичной навигации.
- В рабочем кабинете сотрудника CarCraft той же константой скрыты пункты
  «Импорт спецтехники» и «Управление каталогом».
- Пункты публичной навигации «Каталог» и «О нас» сейчас отображаются всегда.

## Цель

Сотрудник CarCraft должен управлять перечисленными публичными и
административными разделами из существующего экрана «Видимость разделов», без
изменения кода и пересборки frontend. Настройки должны храниться в базе данных,
применяться после загрузки приложения и сохранять текущую видимость по
умолчанию при первом развёртывании или временной недоступности API.

## Требования

### Публичный сайт

Добавить независимые переключатели:

- «О нас» (`/about`) — по умолчанию включён;
- «Каталог» (`/cars`) — по умолчанию включён;
- «Модели» (`/models`) — по умолчанию выключен;
- «Каталог спецтехники» (`/special-equipment`) — по умолчанию выключен.

Переключатели управляют визуальными входами, но не удаляют маршруты и не
заменяют авторизацию. Для каталога спецтехники один переключатель также
управляет всеми поверхностями, которые сейчас скрыты общей константой:

- модулем спецтехники на главной странице;
- спецтехникой в избранном и личном кабинете;
- спецтехникой в корзине;
- фильтрами, ссылками и строками заказов спецтехники.

### Рабочий кабинет сотрудника CarCraft

Добавить независимые переключатели:

- «Импорт спецтехники» — по умолчанию выключен;
- «Управление каталогом» — по умолчанию выключен.

Скрытый пункт не отображается в боковой навигации и недоступен через прямую
навигацию внутри workspace: middleware перенаправляет пользователя на первый
доступный раздел. Права доступа к самим API не ослабляются.

### Существующие ролевые настройки

- Сохранить настройку разделов для ролей `leasing_company`, `dealer` и
  `distributor`.
- Сохранить безопасный дефолт существующих ролевых разделов: видимы, если
  явная настройка отсутствует или запрос завершился ошибкой.
- «Главная», «Личный кабинет», «Профиль» и сам раздел «Видимость разделов» не
  становятся настраиваемыми.

## Планируемые изменения

### Backend

- Обобщить доменный каталог видимости с ролевых workspace-разделов до областей
  `public`, `carcraft_employee`, `leasing_company`, `dealer` и `distributor`.
- Хранить явные переопределения по стабильной паре `scope + section_key` и
  вычислять эффективную матрицу с разными значениями по умолчанию.
- Добавить публичный read-only endpoint матрицы `public`, сохранить endpoint
  текущего workspace и предоставить сотруднику CarCraft единые admin GET/PATCH
  контракты для всех областей.
- Миграцией обобщить существующую таблицу без потери ролевых настроек и
  разрешить новые области видимости.
- Покрыть доменный каталог, значения по умолчанию, сохранение, публичный ответ,
  ролевой ответ и административное обновление backend-тестами.

### Frontend

- Выделить единый feature-модуль видимости с API, Pinia-store, каталогом
  разделов и безопасными значениями по умолчанию.
- Загружать публичную матрицу один раз для публичного layout и использовать её
  во всех общих визуальных поверхностях.
- Удалить `SPECIAL_EQUIPMENT_CATALOG_VISIBLE` и зависимые TODO-проверки.
- Добавить в header условные пункты «О нас», «Каталог», «Модели» и «Каталог
  спецтехники».
- Сделать два пункта спецтехники в меню сотрудника CarCraft настраиваемыми и
  применить к ним существующую защиту прямой workspace-навигации.
- Расширить экран «Видимость разделов» вкладками «Публичный сайт» и
  «Администратор», сохранив состояния загрузки, ошибки, несохранённых изменений
  и доступность переключателей с клавиатуры.
- Обновить архитектурные тесты для новых API-контрактов, дефолтов, пунктов меню
  и отсутствия прежнего хардкода.

## Критерии готовности

- Сотрудник CarCraft видит в «Видимости разделов» пять областей: публичный сайт,
  администратор, лизинговая компания, дилер и дистрибьютор.
- После сохранения каждый из шести новых переключателей независимо меняет
  соответствующую навигацию без изменения кода.
- Первое развёртывание сохраняет текущий результат: «О нас» и автомобильный
  каталог видимы, модели, каталог спецтехники и два административных пункта
  скрыты.
- При недоступности API frontend использует те же безопасные значения по
  умолчанию и не показывает временно скрытые поверхности спецтехники.
- Включение каталога спецтехники восстанавливает весь ранее скрытый визуальный
  сценарий, а не только ссылку в header.
- Скрытые административные пункты не открываются через прямую workspace-ссылку;
  API-права не меняются.
- Существующие ролевые матрицы и сохранённые настройки продолжают работать.
- Backend-проверки `ruff`, `lint-imports`, `mypy`, `pytest`, frontend
  architecture tests, Docker-сборка/запуск и просмотр логов выполнены перед MR.
- Merge request создаётся только в `test`; после его создания спецификация
  переименовывается в `specs/<номер-MR>.md`.

## Границы

- Не блокировать прямые публичные URL `/about`, `/cars`, `/models*` и
  `/special-equipment*` настройкой навигации.
- Не менять роли, scopes JWT, права на импорт или управление каталогом.
- Не добавлять mobile-only интерфейс: поддерживается desktop web с шириной
  viewport от 768 CSS-пикселей.
