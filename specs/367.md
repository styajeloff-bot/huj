# Bitrix #22184 — плоский список доступных категорий транспорта

## Контекст

- Задача: https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/22184/
- Ветка: `bugfix/22184`
- Экран: каталог автомобилей, фильтр «Категория транспорта» на `/cars` и storefront-маршрутах, например `/faw/cars`.

## Текущее поведение

1. Фронтенд получает из `GET /api/v1/cars/facets?fields=categories` всю иерархию транспортных категорий вместе с количеством доступных автомобилей.
2. `frontend/pages/cars/index.vue` преобразует ответ в дерево и отображает его компонентом `VehicleCategoryTree`.
3. В начале списка оказываются служебные корневые группы:
   - `Автотранспорт (ГИБДД)`;
   - `Самоходная техника (Гостехнадзор)`.
4. Пользователю нужно сначала пройти этот дополнительный уровень, чтобы выбрать содержательную категорию, например `B (Легковые автомобили)`.
5. В API также приходят категории с нулевым количеством автомобилей, хотя выбирать их в текущем каталоге бессмысленно.

## Желаемое поведение

В выпадающем списке «Категория транспорта» показываются только доступные пользователю категории транспорта:

- служебные корневые группы с `parent_id = null` не отображаются;
- категории с `vehicles_count = 0` не отображаются;
- на текущих данных FAW пользователь сразу видит `B (Легковые автомобили)`, `C (Грузовые автомобили)`, `D (Автобусы)` с количеством автомобилей;
- выбор категории, текст выбранного фильтра, запрос каталога и сброс выбора продолжают работать с теми же идентификаторами категорий.

## Зачем это нужно

Фильтр должен помогать быстро выбрать тип автомобиля. Группы «ГИБДД» и «Гостехнадзор» являются техническим уровнем классификации и не дают пользователю полезного выбора; нулевые категории создают ложное впечатление доступности.

## Подход и границы

Выбран минимальный frontend-only подход:

1. Оставить backend-фасет, его контракт, иерархию и подсчёты без изменений — они используются для каталоговых запросов и потенциально другими потребителями.
2. В `frontend/pages/cars/index.vue` заменить дерево категорий только в данном выпадающем списке на плоский список, вычисленный из полученных фасетов.
3. В плоский список включать элементы, у которых одновременно:
   - `parent_id !== null`;
   - `vehicles_count > 0`.
4. Использовать существующий `toggleCategorySelection`, чтобы не менять формат `filters.categories`, URL/API-параметр `category`, сохранение фильтров и подсчёт результатов.
5. Не удалять общие `VehicleCategoryTree` и `vehicleCategoryTree.ts`: они не должны меняться без отдельного подтверждения, поскольку могут использоваться при возвращении иерархического сценария.

## Альтернативы и риски

- Не менять backend так, чтобы он возвращал только плоские категории: это изменило бы публичный контракт фасета и могло затронуть другие storefront'ы.
- Не переименовывать и не удалять записи категорий в БД: задача относится только к представлению фильтра.
- Риск: у исторической или будущей категории может быть ненулевой агрегированный счётчик из вложенных категорий. В рамках задачи она всё равно будет доступна как существующая категория фильтра; дополнительная перестройка классификатора не входит в scope.
- Не меняются: другие фильтры, карточки автомобилей, админская загрузка каталога, спецтехника, API и миграции.

## План реализации

1. В `frontend/tests/architecture/vehicle-categories-contract.test.ts` добавить регрессию, фиксирующую требования этого экрана: список строится из доступных не-корневых категорий, а `VehicleCategoryTree` не используется в dropdown каталога.
2. В `frontend/pages/cars/index.vue`:
   - убрать импорт и использование `VehicleCategoryTree` и `buildVehicleCategoryTree` только из данного экрана;
   - добавить вычисляемый `availableVehicleCategories` с фильтрацией по `parent_id` и `vehicles_count`;
   - отобразить обычные чекбоксы в том же стиле dropdown для каждого элемента списка;
   - сохранить `toggleCategorySelection` и закрытие dropdown без изменений.
3. Запустить целевой frontend-тест, полный `bun run test:arch`, frontend build и `git diff --check`.
4. Запустить проект в Docker, проверить через браузер на desktop-ширине: корневые группы не видны, доступная категория выбирается, количество отображается, запрос каталога использует выбранный идентификатор; затем проверить консоль браузера на ошибки.
5. После успешной проверки закоммитить только файлы задачи, запушить `bugfix/22184`, создать MR строго в `test` и приложить ссылку на Bitrix #22184.

## Критерии приёмки

- В dropdown «Категория транспорта» не видны `Автотранспорт (ГИБДД)` и `Самоходная техника (Гостехнадзор)`.
- При данных со скриншота видна категория `B (Легковые автомобили)` и её актуальное количество автомобилей.
- Категории с `vehicles_count = 0` в список не попадают.
- Выбор `B (Легковые автомобили)` сохраняется в поле фильтра и ограничивает выдачу каталога выбранной категорией.
- Снятие выбора возвращает полный каталог и не меняет другие фильтры.
- Не меняются API-ответ `/api/v1/cars/facets`, структура категорий в БД, маршруты каталога и поведение спецтехники.

## Вопросы

Блокирующих вопросов нет. В этой задаче «доступная категория» означает фасет с `vehicles_count > 0`; служебным уровнем считаются только элементы с `parent_id = null`.
