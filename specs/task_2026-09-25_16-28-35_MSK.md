# Снятие 60-секундного кулдауна SMS для тестовых номеров

## Постановка

Тестовый SMS-код `0000` является одноразовым: после первого успешного ввода
`handle_verify_phone` удаляет строку из `verification_codes`. При этом на
повторный вызов `/login` действует 60-секундный кулдаун: если предыдущий тест
упал до ввода кода, в таблице осталась «зависшая» запись, и следующий вызов
`/login` возвращает HTTP 403 (`codeAlreadySent: true`), не создав новую строку.
В итоге ввод `0000` падает с HTTP 400 (`invalid_code`), и весь E2E-прогон
ломается, начиная со второго теста, который не может повторно залогиниться.

## Требования

1. Для телефонов, совпадающих с `is_test_phone(phone)` (`+7666…`), кулдаун
   снимается полностью: `/login` всегда создаёт свежую строку `verification_codes`
   со срочностью `expires_at = now() + 10 min` и возвращает HTTP 200.
2. Для всех остальных телефонов кулдаун 60 секунд остаётся неизменным.
3. Существующий тест `test_login_cooldown` переводится на обычный телефонный
   номер. Чтобы `/login` не пытался дозвониться до реального SMTP-шлюза,
   добавляется `monkeypatch` на `_send_sms_background`.
4. Не затрагивается `verify_code`: он по-прежнему требует наличия живой строки
   в `verification_codes`, что позволяет тестировать негативные сценарии
   (истёкший код, «код не запрашивался»).
5. Схема БД не меняется — миграции не нужны.

## Планируемые изменения

### Backend — логика авторизации

#### [MODIFY] backend/application/commands/auth.py

- Функция `_should_send_code` принимает дополнительный аргумент `phone: str`.
- Добавляет early-return `True` при `is_test_phone(phone)` до любых проверок
  временного штампа.
- Вызов в `handle_login` обновляется: `_should_send_code(last_code_at, cmd.phone)`.

### Backend — тесты

#### [MODIFY] backend/tests/test_auth.py

- `test_login_cooldown` переходит на реальный номер `+79001112233`.
- Добавляется пользователь с этим номером через `db_session` прямо внутри теста.
- `monkeypatch.setattr("application.commands.auth._send_sms_background", AsyncMock())`
  предотвращает реальный SMTP-вызов.
- Проверки: первый `/login` → 200, второй `/login` немедленно → 403,
  `codeAlreadySent: true`.
- Добавляется новый тест `test_login_no_cooldown_for_test_phone`:
  проверяет, что для `+7666…` два последовательных вызова `/login` оба возвращают 200.
