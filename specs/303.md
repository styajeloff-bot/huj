# Переход от проектной документации к спецификациям задач

## Контекст

Накопленная проектная документация не используется командой и создаёт лишнюю
нагрузку при выполнении задач. Для трассировки изменений достаточно одной
спецификации на задачу.

## Требования

- Удалить каталог `документация/` со всем содержимым.
- Удалить проверки и генераторы, существующие только для поддержки этого
  каталога.
- Создать единый каталог `specs/` для спецификаций задач.
- До создания merge request называть спецификацию
  `temp_<порядковый номер>.md`.
- После создания merge request переименовывать спецификацию в
  `<номер merge request>.md`.
- Убрать из `AGENTS.md` требования создавать отдельные планы, отчёты, ADR,
  реестры, ER-диаграммы и другую проектную документацию.
- Не требовать Bitrix-задачу для внутренних служебных изменений, если
  пользователь явно указал, что задача не связана с Bitrix.

## Критерии готовности

- Каталог `документация/` отсутствует.
- В репозитории нет обязательных CI-проверок удалённой документации.
- `AGENTS.md` описывает один обязательный артефакт задачи — спецификацию в
  `specs/`.
- Временная спецификация получает номер merge request после его создания.
- Проверки затронутых конфигураций и тестов проходят.
