## Постановка

В корневом `AGENTS.md` с момента объединения бэкенда в монорепозиторий присутствовала ссылка на файл `backend/AGENTS.md`. При этом сам файл в репозитории отсутствовал: документация бэкенда была разбита исключительно по четырём архитектурным слоям (`backend/application/AGENTS.md`, `backend/domain/AGENTS.md`, `backend/infrastructure/AGENTS.md`, `backend/presentation/AGENTS.md`), а специфичные для бэкенда правила (статические проверки кода, регламент `alembic check`, взаимодействие с ClickHouse/DWH, чтение секретов через `settings`, логирование `"carcraft-backend"`, обработка редиректов со слешами, публичные эндпоинты, поиск компаний через DaData) находились непосредственно в корневом `AGENTS.md`.

Цель задачи:
1. Создать входной документ `backend/AGENTS.md` по аналогии с `frontend/AGENTS.md`, объединяющий общее описание сервиса, запуск, проверки качества кода, навигацию по послойным инструкциям и бэкенд-специфичные правила.
2. Перенести из корневого `AGENTS.md` детальные правила, относящиеся исключительно к бэкенду, оставив в корневом файле краткие сквозные ориентиры и актуальную ссылку на `backend/AGENTS.md`.

## Требования

### 1. Содержимое `backend/AGENTS.md`

Документ составляется на русском языке и включает следующие разделы:

1. **Заголовок и стек сервиса:**
   - FastAPI :3002, Python 3.12+, Uvicorn, PostgreSQL (SQLAlchemy async + Alembic), ClickHouse, Redis, Kafka.
   - Принцип чистой архитектуры (Clean Architecture / DDD-лайт).

2. **Архитектурные слои и навигация:**
   - Ссылки на послойные инструкции:
     - `application/AGENTS.md` (use cases, CQRS-команды, запросы, транзакции, маппинг ошибок, auth/notifications);
     - `domain/AGENTS.md` (доменные сущности, бизнес-правила, инварианты, отсутствие I/O, Protocol-порты);
     - `infrastructure/AGENTS.md` (БД, SQLAlchemy ORM-модели, репозитории с возвратом `dict`, адаптеры внешних сервисов, settings);
     - `presentation/AGENTS.md` (FastAPI-роутеры, Pydantic-схемы, OpenAPI-документация, auth dependencies, webhooks).

3. **Локальный запуск и окружение:**
   - Команды запуска сервиса через Docker Compose (`docker compose up -d --build --force-recreate backend`).
   - Управление зависимостями через `uv`.

4. **Обязательные проверки бэкенда перед коммитом:**
   - Статические проверки:
     ```bash
     cd backend
     uv run ruff check . --fix
     uv run lint-imports
     uv run mypy .
     ```
   - Проверка соответствия ORM-моделей и схемы БД:
     ```bash
     uv run alembic upgrade head
     uv run alembic check
     ```
     Требование обязательного отсутствия расхождений (`No new upgrade operations detected.`). Запрет маскировки через `alembic stamp` или фильтры autogenerate.

5. **Правила и соглашения бэкенда:**
   - **Идентификаторы сущностей:** использование `uuid.UUID` в Python (строгий запрет int без доказанного контракта в схеме).
   - **Секреты и конфигурация:** только `from infrastructure.settings import settings`, категорический запрет прямого чтения `os.environ` / `os.getenv`.
   - **Аутентификация:** чтение токена сначала из cookie `accessToken`, затем из `Authorization: Bearer`. Ключи ES256 из `settings.jwt_keys_dir`, запрет HS256.
   - **Публичные эндпоинты:** список эндпоинтов, не требующих авторизации (`/health`, `/section-visibility/public`, каталог и витрины, карточки и изображения спецтехники, поиск компаний).
   - **Маршрутизация и редиректы:** канонические пути внутри FastAPI без внешних HTTP 307 из-за trailing slash. Запрет широкого `--forwarded-allow-ips "*"`.
   - **Webhooks:** авторизация по подписям провайдеров (без JWT), соблюдение контракта ответов (например, HTTP 200 для ModulBank).
   - **Логирование:** единственный именованный логгер `"carcraft-backend"`, исключение healthcheck из `uvicorn.access`.
   - **ClickHouse и DWH:** все операции записи принадлежат только Kafka consumer (`event-worker`). FastAPI выполняет исключительно аналитическое чтение через `infrastructure/clickhouse_readonly.py`.
   - **Поиск компаний:** интеграция с DaData изолирована в `GET /api/v1/company/search`. Фронтенд передаёт готовый объект компании.

6. **Запрещённые практики на бэкенде:**
   - Нарушение направлений зависимостей между слоями (контролируется `lint-imports`).
   - Использование типа `float` для денежных сумм (только `Decimal`).
   - Использование ORM-объектов как DTO между слоями (репозитории отдают `dict`).
   - Вызовы `session.commit()` в репозиториях или use-case хендлерах (коммит выполняется в роутерах `presentation`).
   - Добавление unit- и архитектурных тестов без прямого запроса пользователя.
