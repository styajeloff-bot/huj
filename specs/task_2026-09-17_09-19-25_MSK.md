# Доработки задачи 22130

Источник требований: сообщение пользователя в текущей задаче и ссылка https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/22130/ . Содержимое Bitrix получить не удалось; постановка взята из сообщения пользователя.

## Требования

1. В настройках видимости витрины добавить независимый переключатель «Видимость секции „Марка“ в фильтрах». По умолчанию включён, в том числе для существующих витрин без сохранённого значения.
2. Выключение скрывает выбор марки в фильтрах `/cars` выбранной витрины, включая быстрый выбор популярных марок. Включение возвращает его. Настройка действует также на маршрут `/<storefront_slug>/cars`.
3. Настройка управляет интерфейсом: ограничения ассортимента витрины и фильтрация по параметрам ссылки сохраняются. Переход из карточки модели в отфильтрованный каталог продолжает работать. Остальные фильтры доступны.
4. Значение сохраняется независимо для каждой витрины и не связано с переключателем «Выбор марки перед моделями».
5. В карточке модели на `/models/<...>` заменить «Объём двигателя», «Максимальная мощность», «Разгон до 100 км/ч» двумя характеристиками: «Категория» и «Тип кузова».
6. Категория — читаемое название категории модели из справочника (в актуальной схеме VehicleCategory.id хранит это название, отдельного поля name нет). Тип кузова — непустые уникальные значения конфигураций доступных автомобилей модели в текущей витрине, в стабильном порядке, через запятую. Если значение отсутствует, показывать «—», не идентификатор.
7. Замена применяется к общему компоненту карточек, включая `/models`, когда там отображается модельный ряд без выбора марки. Изображение, цена, количество автомобилей и ссылки сохраняют прежнее поведение.

## Подтверждённые точки изменений

- `frontend/features/sectionVisibility/config.ts` и `backend/domain/section_visibility.py`: существующие каталоги ключей видимости содержат `model_brand_selection`; новый ключ предлагается назвать `cars_brand_filter`.
- `frontend/features/sectionVisibility/AdminSectionVisibilityPanel.vue`: вывод настроек видимости выбранной витрины.
- `frontend/pages/cars/index.vue`: селектор марки и блок популярных марок.
- `frontend/features/cars/components/ModelShowcase.vue`: массив трёх характеристик карточки.
- `frontend/pages/models/[brandId].vue`: фактический динамический маршрут представляет марку и использует общий ModelShowcase.
- `backend/infrastructure/repositories/cars_public_repository.py`, `backend/presentation/schemas/cars.py`, `frontend/features/cars/api/carsApi.ts`: запрос и контракт model-showcase; сейчас ответ содержит volume, horse_power, time_to_100, но не новые поля.

## Критерии готовности

- Сохранённое выключение переживает перезагрузку; выбор марки и быстрые кнопки скрыты только в нужной витрине. Повторное включение восстанавливает выбор.
- У витрины без нового значения фильтр виден; чужая витрина и выбор марки перед моделями независимы.
- Переход модель → автомобили с параметрами марки/модели и другие фильтры работают при скрытом выборе марки.
- Карточки показывают две новые подписи и значения из API; три старые подписи отсутствуют.
- Покрыты отсутствующие значения, несколько типов кузова, отсутствие повторов, изоляция ассортимента и сохранение количества/цен при агрегации.
- Проверки и браузерная приёмка успешны; MR направлен в test.

## Уточнение 17.09.2026: название кузова

Подтверждённый источник: frontend/pages/cars/[id].vue выводит car.configuration_name. Модельный ряд должен использовать тот же источник — Configuration.configuration_name, сохраняя поле ответа body_type и агрегацию уникальных непустых названий по доступному ассортименту витрины. Configuration.body_type содержит технический код и не используется для подписи. При отсутствии названия показывать «—».
