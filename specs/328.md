# Bitrix #21512 — создание заявки дилером от имени компании клиента

**Задача:** https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/21512/

## Постановка

Дилер должен иметь возможность создать заявку от имени компании клиента, найденной через существующий поиск по ИНН. Компания клиента не должна добавляться в профиль и список компаний дилера.

## Текущее состояние

- Backend уже принимает объект компании клиента, находит или создаёт компанию по ИНН, сохраняет её в `leasing_applications.company_id` и отдельно сохраняет компанию дилера в `dealer_company_id`.
- При выборе найденной компании клиента frontend одновременно передаёт объект клиента и `company_id` дилера. Backend сейчас безопасно заменяет ID на компанию клиента, но payload двусмысленный.
- При открытии формы у дилера очищается компания вместо того, чтобы быть предвыбранной собственной компанией дилера.
- Старая ветка `bugfix/21512` не влита и основана на устаревшем `test`; она не переносится целиком.

## Требуемое поведение

1. В новой заявке собственная компания дилера отображается по умолчанию.
2. Дилер может очистить значение, найти компанию клиента по ИНН через `GET /api/v1/company/search` и выбрать её.
3. Если выбрана компания клиента, frontend отправляет в создание заявки полный объект компании без `company_id` компании дилера.
4. В созданной заявке `company_id` — компания клиента, а `dealer_company_id` — компания дилера.
5. Связь `UserCompany` между дилером и клиентской компанией не создаётся.
6. Обычное создание заявки от собственной компании остаётся прежним.

## Выбранный подход

На свежей ветке `bugfix/21512-completion` от `origin/test` внести минимальное frontend-исправление, не изменяя backend API, модели или миграции:

- уточнить payload в `frontend/features/checkout/composables/useDraftApplication.ts`;
- восстановить предвыбор и повторный выбор собственной компании дилера в `frontend/features/checkout/components/CheckoutConditions.vue`;
- добавить frontend-регрессии payload и состояния выбора компании;
- добавить backend-регрессию, подтверждающую разделение `company_id`/`dealer_company_id` и отсутствие `UserCompany`-привязки клиента.

## Альтернативы и риски

- **Cherry-pick старого коммита `4c8820f8`** не используется: ветка устарела и не покрывает предвыбор собственной компании.
- **Изменение backend API или схемы БД** не требуется: нужный контракт уже существует.
- Основной риск — нарушить обычное создание заявки от собственной компании. Он закрывается отдельной регрессией fallback-payload и browser-проверкой.

## Критерии готовности

- Дилер видит собственную компанию по умолчанию и может заменить её компанией клиента.
- При выбранном клиенте payload не содержит `company_id` дилера.
- Заявка содержит корректные `company_id` клиента и `dealer_company_id` дилера.
- Компания клиента не появляется в профиле дилера.
- Новые тесты, обязательные проверки, Docker и browser-проверка имеют подтверждённый результат.
