# Свободный выбор цветов витрины без ограничения контраста

## Контекст

- Внутренняя задача, не связанная с Bitrix.
- Основание — запрос пользователя от 08.09.2026: убрать ограничение по
  контрасту из настроек оформления витрин.
- Базовая версия — актуальный `origin/test` на merge-коммите MR !362
  `38326d25f63f4744bbb24c915a2f2357c8387187`.
- Сейчас frontend и backend запрещают сохранять цвета, если основной текст
  имеет контраст ниже 4.5:1 с фонами или основной цвет — ниже 3:1 с фонами.

## Требуемое поведение

1. Администратор может сохранить любую комбинацию четырёх цветов витрины,
   если каждое значение соответствует формату `#RRGGBB`.
2. Frontend не показывает ошибки контраста и не блокирует кнопку сохранения
   из-за соотношения выбранных цветов.
3. Backend не отклоняет корректную по структуре appearance-конфигурацию из-за
   контраста цветов.
4. Проверка формата, нормализация hex в верхний регистр, полный набор ключей,
   допустимый `border_radius`, UUID шрифта и атомарное сохранение остаются без
   изменений.
5. Публичная тема продолжает автоматически выбирать из чёрного и белого цвет
   текста на основном цвете с лучшим контрастом. Это вычисление не ограничивает
   выбор администратора.
6. API-контракт и схема базы данных не меняются; новая миграция не требуется.

## Планируемые изменения

### Backend

- Удалить четыре блокирующие проверки контраста из
  `validate_storefront_appearance`.
- Сохранить функции расчёта контраста, используемые для выбора чёрного или
  белого текста на основном цвете.
- Заменить доменный и интеграционный тесты отклонения низкого контраста тестами
  успешного сохранения таких цветов и увеличения версии витрины.

### Frontend

- Оставить в `validateStorefrontColors` только проверку формата `#RRGGBB`.
- Удалить сообщения о минимальном контрасте и заменить общее сообщение формы на
  «Исправьте формат цветов».
- Обновить архитектурные тесты: низкоконтрастные цвета допустимы, невалидный
  формат по-прежнему блокируется, расчёт производных цветов публичной темы
  сохраняется.

## Проверки

Backend:

```bash
cd backend
uv run ruff check . --fix
uv run lint-imports
uv run mypy . --ignore-missing-imports
uv run pytest -q
```

Frontend:

```bash
cd frontend
bun run test:arch
bunx vue-tsc --noEmit
bun run build:frontend
```

После автоматических проверок собрать и запустить `backend`, `frontend` и
`nginx` в Docker. В браузере сохранить низкоконтрастную комбинацию и убедиться,
что публичная витрина получает её без ошибки.

## Критерии готовности

- Любые четыре валидных `#RRGGBB` значения сохраняются независимо от их
  контраста.
- Frontend и backend одинаково принимают низкоконтрастную комбинацию.
- Ошибочный формат цвета по-прежнему отклоняется до сохранения.
- Автоматический выбор чёрного или белого текста для primary-контролов и все
  остальные настройки оформления работают как прежде.
- Тесты, статические проверки, Docker-запуск и browser-проверка успешны.
- Создан MR только в `test`; после создания файл переименован в
  `specs/<номер-MR>.md`.

## Вне объёма

- Автоматическая коррекция выбранных цветов.
- Предупреждения или рекомендации по WCAG без блокировки сохранения.
- Изменение числа цветовых полей, API-формы appearance или схемы базы данных.
