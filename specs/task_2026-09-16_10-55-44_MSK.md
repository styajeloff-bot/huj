# Bitrix #21700 — отображение цели и регионов в представлениях заявки

## Постановка

Задача: https://carcraftpro.bitrix24.ru/workgroups/group/124/tasks/task/view/21700/

Нужно устранить два дефекта, подтверждённые скриншотами заявки `0276951412-1409-001`.

## Текущее поведение

### Пользовательское окно предложения

В `frontend/features/checkout/components/CheckoutOfferModal.vue` в карточках техники:

- поле «Цель приобретения» показывает технические значения из API: `management`, `other`;
- регион уже выводится отдельным компонентом.

Причина: локальная функция `vehicleLeasingPurpose()` возвращает исходное значение `leasing_purpose`, не используя общий русскоязычный форматтер.

### Кабинет лизинговой компании

На скриншоте карточки техники не содержат ни цели приобретения, ни регионов.

В актуальном `origin/test` страница `frontend/pages/workspace/leasing-applications/[id]/index.vue` уже содержит оба поля и использует `formatLeasingPurpose()` и `VehicleRegionsDisplay`. Поэтому до добавления повторной правки нужно проверить собранный frontend на свежем `test`:

- если поля есть в DOM и на экране — дефект относится к отставшему развёртыванию/кэшу стенда, код менять не нужно;
- если поля отсутствуют при актуальном frontend — проверить контракт `GET` состояния заявки для роли ЛК и исправить конкретный разрыв данных или отображения.

## Желаемое поведение

1. В пользовательском окне цели отображаются на русском языке:
   - `management` — «Для руководства»;
   - `other` — «Прочее» либо «Прочее: <комментарий>»;
   - пустое значение — «Не указано».
2. В кабинете лизинговой компании у каждой автомобильной позиции доступны:
   - «Цель приобретения» в человекочитаемом виде;
   - «Регион» с существующим компактным/раскрываемым отображением нескольких регионов.
3. Значения для разных автомобилей не смешиваются.
4. Карточки спецтехники и существующие финансовые условия не меняются.

## Бизнес-причина

Цель покупки и регионы нужны лизинговой компании для оценки риска и условий. Технические английские коды непонятны пользователю, а отсутствие полей у ЛК лишает её значимой информации по каждой позиции.

## Варианты

### Вариант А — рекомендованный

- В пользовательском модальном окне заменить локальный вывод кода цели на общий `formatLeasingPurpose()`.
- Проверить актуальную реализацию кабинета ЛК через собранное приложение и сетевой ответ.
- Добавлять backend или вторую frontend-правку для ЛК только при подтверждённом разрыве контракта на свежем `test`.

Плюсы: минимальная правка, единые русские названия во всех экранах, отсутствует дублирование словаря целей.

Риск: если стенд работает на старом образе, изменение исходников само по себе не изменит уже запущенное окружение. Это будет отдельно зафиксировано как вопрос развёртывания.

### Вариант Б — повторно менять страницу ЛК без проверки

Не рекомендуется: актуальный исходный код уже содержит нужные поля. Повторная правка создаст риск дублирования и не устранит возможное отставание развёртывания.

## Планируемые изменения

1. Добавить регрессионный frontend-тест для `CheckoutOfferModal.vue`, который фиксирует использование общего форматтера цели вместо прямого вывода `leasing_purpose`.
2. Перевести `vehicleLeasingPurpose()` на общий форматтер с передачей `leasing_purpose` и `leasing_purpose_comment` конкретной позиции.
3. Выполнить проверку кабинета ЛК на свежем frontend и с данными заявки:
   - DOM содержит оба поля;
   - сетевой ответ содержит цель и регионы для каждой автомобильной позиции;
   - при отсутствии полей определить, в API или интерфейсе находится разрыв и покрыть его отдельным регрессионным тестом.
4. Запустить архитектурные тесты, сборку и локальную browser-проверку; перед коммитом проверить diff.
5. Создать MR из `bugfix/21700-view-data` строго в `test`.

## Критерии готовности

- [ ] В пользовательском окне больше не видны коды `management` и `other`; вместо них показаны русские значения.
- [ ] Для значения `other` с комментарием виден комментарий пользователя.
- [ ] В актуальном фронтенде кабинета ЛК у автомобильных позиций видны «Цель приобретения» и «Регион».
- [ ] Несколько регионов выводятся существующим компактным компонентом и раскрываются без потери значений.
- [ ] Цель и регионы одной позиции не отображаются в другой позиции.
- [ ] Изменённые сценарии покрыты регрессионным тестом.
- [ ] Проходят целевые и полные frontend architecture tests, production build, `git diff --check` и браузерная проверка Hermes.

## Вопросы

Блокирующих вопросов нет.

Неблокирующий вопрос: если на свежем `test` поля ЛК есть в коде и в собранном frontend, потребуется обновление стенда. Такое обновление является инфраструктурным действием и будет выполняться только после отдельного подтверждения.
