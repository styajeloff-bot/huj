### Подтверждённые регрессии дополнительного объёма от 04.09.2026

## Цель и бизнес-результат

Администратор управляет публичным представлением каждой витрины в одном месте — в разделе «Витрины»: выбирает единственную главную страницу, задаёт названия публичных страниц, настраивает их видимость и меняет названия/видимость двух блоков автомобильного каталога.

При открытии корня основной или дополнительной витрины пользователь попадает на выбранную для этой витрины главную страницу. Настройки одной витрины не влияют на другие. Публичная навигация и остальные пользовательские подписи используют заданные администратором названия.

## Термины и стабильные ключи

Публичные страницы представлены стабильными техническими ключами, которые не меняются при переименовании:

| Ключ | Текущий маршрут | Название по умолчанию |
| --- | --- | --- |
| `home` | `/` | Главная |
| `about` | `/about` | О нас |
| `catalog` | `/cars` | Каталог |
| `models` | `/models` | Модели |
| `special_equipment_catalog` | `/special-equipment` | Спецтехника |

`model_brand_selection` остаётся настройкой представления страницы моделей и не является самостоятельной публичной страницей: её нельзя выбрать главной или переименовать как страницу.

Внутри страницы `catalog` используются два стабильных ключа блоков:

| Ключ | Название по умолчанию |
| --- | --- |
| `special_offers` | Выбрать автомобиль по специальной цене |
| `all_vehicles` | Выбрать автомобиль из каталога |

## Функциональные требования

### 1. Выбор главной страницы

- Для каждой витрины хранится ровно один `home_page_key` из каталога публичных страниц.
- Значение по умолчанию для существующих и основной витрин — `home`, чтобы миграция не меняла текущий маршрут `/` без решения администратора.
- Запрос `/` основной витрины и `/{storefrontSlug}` дополнительной витрины открывает выбранную страницу в контексте этой же витрины.
- Для страницы, отличной от `home`, допускается storefront-aware перенаправление на её канонический путь: например, `/` → `/cars`, а `/faw` → `/faw/cars`. Перенаправление не должно терять query/hash и не должно создавать цикл.
- Логотип и ссылка выбранной главной страницы в навигации ведут через корень текущей витрины.
- Выбранная главная страница обязана быть видимой. При выборе скрытой страницы она автоматически включается в той же серверной транзакции.
- Попытка скрыть текущую главную страницу через любой административный API отклоняется понятной доменной ошибкой, пока главной не выбрана другая страница.
- Все остальные публичные страницы можно скрыть одновременно; выбранная главная остаётся единственной видимой страницей и доступным пунктом публичной навигации.
- Если главной выбрана страница `models`, текущая настройка `model_brand_selection` продолжает определять, будет ли сначала показан выбор марки.

### 2. Переименование публичных страниц

- Названия публичных страниц являются настройками конкретной витрины и хранятся по UUID витрины.
- Для каждой витрины администратор может независимо изменить название каждой страницы из таблицы публичных страниц, включая `home`.
- Переименование страницы в одной витрине не изменяет название страницы с тем же техническим ключом в основной или любой другой дополнительной витрине.
- Название обязательно после trim, имеет серверное ограничение длины и не может состоять только из пробелов.
- Переименование не меняет технический ключ, URL, права доступа или данные каталога.
- Настроенное название используется во всех местах, где интерфейс обозначает именно эту публичную страницу: в шапке, административном списке/выборе главной, заголовке страницы, breadcrumbs, ссылках возврата, доступном пользователю title/aria-label и других общих компонентах навигации.
- Произвольные маркетинговые тексты и названия сущностей каталога не переписываются по совпадению строки.
- Публичный storefront response отдаёт уже эффективные названия всех страниц, чтобы SSR и клиентская гидрация показывали одинаковый текст без мигания значений по умолчанию.

### 3. Видимость разделов внутри «Витрин»

- Отдельный пункт «Видимость разделов» удаляется из workspace-меню администратора.
- В карточке выбранной витрины появляется отдельная понятная вкладка/секция «Страницы и видимость» рядом с основными настройками витрины.
- Внутри выбранной витрины настраиваются области `public`, `leasing_company`, `dealer` и `distributor` без дополнительного селектора витрины: контекст задаётся выбранной карточкой.
- Глобальная область `carcraft_employee` не теряется и визуально отделяется с пояснением «единая для всех витрин». Она доступна в разделе «Витрины», но не создаёт ложного впечатления, что значение различается по витринам.
- Существующие значения, dirty-state, загрузка, retry, ошибки, сохранение и доступность с клавиатуры сохраняются.
- Старый маршрут `/workspace/section-visibility` не остаётся вторым экраном редактирования: он перенаправляет администратора в соответствующую секцию `/workspace/storefronts`, чтобы старые закладки не приводили к тупику.
- Внутри «Витрин» настройки группируются визуально и не превращают форму логотипа/контактов/складов в одну длинную неразличимую форму. Поддерживается только desktop viewport 768+.

### 4. Настройка блоков страницы «Каталог»

- Названия и видимость блоков каталога являются настройками конкретной витрины и хранятся по UUID витрины.
- Для каждой витрины независимо настраиваются название и видимость блоков `special_offers` и `all_vehicles`.
- Изменение названия или видимости блока в одной витрине не влияет на основную или любую другую дополнительную витрину.
- По умолчанию оба блока видимы и используют текущие названия.
- Разрешено скрыть любой один блок. Одновременно скрыть оба блока нельзя: сервер отклоняет конфигурацию, оставляющую страницу каталога без доступного режима.
- Когда видимы оба блока, каталог сохраняет текущий переключатель режимов и их существующее поведение.
- Когда видим только один блок, переключатель из одного пункта не показывается, а фильтры и запрос каталога автоматически используют разрешённый режим независимо от устаревшего query/client state.
- Скрытый блок нельзя вернуть только подстановкой URL-параметра или сохранённого состояния браузера.
- Изменённые названия выводятся в переключателе и связанных доступных подписях; логика фильтрации и серверные признаки специального предложения не переименовываются.

### 5. Цена на странице `/models`

- Карточка модели показывает диапазон `min_price — max_price`, рассчитанный
  только по ценам до скидки.
- Основной источник обеих границ — положительный `Vehicle.base_price`. Если он
  отсутствует или неположителен, допускается существующий неснижающий fallback
  на положительный `Modification.offers_price_from`.
- `discount_price` и `special_price` не входят в агрегат диапазона model
  showcase. Цена конкретного ТС, сортировка и фильтрация `/cars`, корзина и
  расчёт скидки не меняются.
- Для разных положительных границ выводится `<min_price> — <max_price>`; при
  одинаковых границах — `от <price>`, при единственной минимальной границе —
  `от <min_price>`, при единственной максимальной — `до <max_price>`.
- Если положительных границ нет, выводится «Цена по запросу».
- Формат валюты и остальные данные карточки остаются без изменений. Повышение
  отображаемого диапазона относительно скидочных цен является ожидаемым
  бизнес-результатом.

### 6. Визуальная синхронизация query-фильтров каталога

- При открытии `/cars` и `/{storefrontSlug}/cars` с query `mark`, `model` и,
  при наличии, `generation` выбранные значения применяются к выдаче и
  отображаются в соответствующих контролах и активных тегах.
- Зависимые facets загружаются в последовательности выбранных значений: список
  моделей учитывает марку, а поколения и комплектации — уже выбранные
  родительские значения.
- Требование действует для прямой загрузки URL, перехода с `/models` и
  изменения релевантных query-параметров в открытом каталоге.
- Query имеет приоритет над сохранёнными фильтрами localStorage. Непрозрачные
  строковые идентификаторы не преобразуются в числа.

### 7. Эквивалентность корня витрины со слешем и без него

- `/{storefrontSlug}` и `/{storefrontSlug}/` считаются одним корнем и открывают
  выбранный `home_page_key` в контексте той же витрины.
- Если прежний landing скрыт и главной выбрана другая страница, завершающий
  слеш не позволяет открыть скрытый landing.
- Query и hash сохраняются, цикл перенаправлений не создаётся.
- Вложенные пути, например `/faw/cars/`, не считаются корнем витрины.

## Серверный контракт и хранение

- Добавить миграцию после текущего Alembic head `108` для витринной конфигурации публичного UI.
- Хранить конфигурацию по UUID витрины, не по slug. Конкретная форма хранения может быть отдельной таблицей с FK на `catalog_storefronts` либо типизированными колонками витрины, но должна обеспечивать:
  - один `home_page_key` на витрину;
  - полный набор валидированных названий страниц;
  - названия и видимость двух блоков каталога;
  - timestamps/автора изменения в принятом для административных настроек виде;
  - безопасные значения по умолчанию для существующих строк.
- Доменные каталоги ключей и defaults являются единственным источником допустимых страниц и блоков; произвольные ключи из запроса не сохраняются.
- Расширить public и admin DTO витрины эффективной публичной конфигурацией.
- Расширить административный PATCH витрины либо добавить один вложенный resource публичной конфигурации. Смена главной страницы и автоматическое включение её видимости выполняются атомарно.
- В обработчике существующего PATCH видимости добавить проверку инварианта главной страницы, чтобы его нельзя было обойти прямым API-вызовом.
- Создание новой витрины копирует актуальные настройки основной витрины как независимый snapshot, аналогично текущей инициализации матриц видимости; дальнейшие изменения основной витрины не переписывают уже созданные витрины.
- Публичный read-контракт возвращает только данные отображения, без административных timestamps и автора.
- Все идентификаторы витрин остаются UUID; числовые преобразования идентификаторов не добавляются.

## Тестовое покрытие

### Backend

- Доменные тесты: допустимые ключи, trim/длина названий, один home key, минимум один видимый блок каталога.
- Application/repository: независимые настройки двух витрин, backfill defaults, snapshot новой витрины, атомарное включение выбранной главной и запрет скрытия текущей главной.
- HTTP integration: public/admin responses, обновление конфигурации, неизвестные ключи/витрина, права сотрудника CarCraft и сохранение UUID-контракта.
- Проверка миграционного графа `108 -> 109`, upgrade/downgrade и существующих данных.
- Интеграционный тест model showcase подтверждает, что более низкие
  `discount_price` не влияют на границы из `base_price`, а нулевой или
  отсутствующий `base_price` использует положительный `offers_price_from`.

### Frontend architecture/regression

- В workspace остаётся один экран редактирования витринной конфигурации, а отдельный пункт «Видимость разделов» отсутствует.
- Имена страниц берутся из storefront context, а не из дублирующихся строк в шапке, models/catalog breadcrumbs и административной форме.
- Root-routing строит путь через storefront-aware route helper и одинаково
  обрабатывает `/faw` и `/faw/`, не принимая вложенный путь за корень.
- Каталог корректно работает при двух режимах и при каждом единственном видимом режиме; скрытый режим нельзя активировать query-параметром.
- `formatModelShowcasePrice` покрывает диапазон, равные границы, одиночную
  границу и отсутствие положительных значений.
- Инициализация каталога загружает зависимые facets для query без числового
  преобразования идентификаторов.

## Критерии готовности

- Каждая витрина имеет ровно одну выбранную главную страницу; корень открывает её, не теряя storefront context.
- Главную страницу нельзя скрыть, но все остальные публичные страницы можно скрыть одновременно.
- Названия публичных страниц хранятся и настраиваются относительно выбранной витрины; изменение одной витрины не затрагивает остальные и отображается во всех общих пользовательских местах, включая навигацию.
- Видимость public и бизнес-ролей редактируется внутри выбранной витрины; глобальная область администратора сохранена и явно обозначена как общая.
- Отдельный пункт «Видимость разделов» удалён, старый URL не становится тупиком.
- Названия и видимость двух блоков каталога хранятся относительно выбранной витрины; блоки переименовываются и скрываются по одному, а конфигурация с двумя скрытыми блоками невозможна.
- `/models` показывает диапазон цен до скидок; для текущих данных `test`
  ожидаемый диапазон `BESTUNE T90` после пересчёта —
  `3 892 000 ₽ — 4 181 000 ₽` вместо скидочного
  `2 742 000 ₽ — 3 031 000 ₽`.
- Переход с карточки `BESTUNE T90` визуально показывает `FAW` и `BESTUNE T90`
  в контролах и активных тегах, сохраняя корректную фильтрацию выдачи.
- `/faw` и `/faw/` открывают одну выбранную администратором главную; скрытый
  прежний landing недоступен через завершающий слеш.
- Все изменения покрыты backend, frontend regression и desktop E2E тестами.
- Выполнены обязательные `ruff`, `lint-imports`, `mypy`, `pytest`, frontend architecture tests, Docker build/up и просмотр логов.
- MR создан только в `test`, содержит ссылку на Bitrix #22130 и список фактически выполненных проверок; после зелёных CI и обязательного review включено автоматическое объединение.

- Не меняются slug витрин, складская привязка, состав каталога автомобилей,
