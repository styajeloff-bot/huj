# Восстановление зелёного backend test baseline

## Контекст

- Полный backend suite в актуальном `test` стабильно имеет три падения.
- Общий `resolve_distributor_scope` корректно ограничен связанными дилерами, но
  application access не добавляет к ним собственный склад дистрибьютора.
- Специализированный distributor support handler не передаёт в repository
  обязательный флаг ограничения, а его unit test не передаёт новый
  `actor_company_id`.
- Красный baseline не позволяет включить полный pytest в общий local pre-push
  hook без блокировки всех разработчиков.

## Требования

- Только application access/item projection должны включать собственный склад
  дистрибьютора вместе со связанными дилерами. Общий analytics/import scope и
  scope сотрудника CarCraft не менять.
- Distributor support handler должен явно включать ограничение программ по
  текущей компании.
- Актуализировать unit test под обязательный `actor_company_id`.
- Не ослаблять assertions и не добавлять allowlist известных падений.

## Критерии готовности

- Три воспроизводимых теста проходят изолированно.
- Полный `uv run pytest -q` зелёный.
- Ruff, import-linter и mypy зелёные.
- Создан отдельный MR в `test`; изменения не смешаны с migration hotfix или
  quality-gate.
